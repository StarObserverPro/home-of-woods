# 家宅平安：营地三件套的外部模块

本轮继承 [营地取放、图纸和木屋修缮](CAMP_INTERACTIONS.md) 已有的事务与存档路径；它依赖前置 PR #10。目标不是复制建筑，也不把家具放到建筑里面，而是让既有帐篷、木屋与篝火通过单件装配逐渐改变外形。外部部件具有独立图纸、投入记录、安装状态和渲染根节点。

## 规则与操作

1. 在场景里选中帐篷、木屋或篝火，外部改造面板会显示这座设施名下的部件。远处可以查看全部方案，但要先走近才能施工。
2. 在仓库的「图纸」页查看已学会和未获得的外装图纸。首次附赠绷绳、重垒石圈两张基础图纸；其他图纸可在行商处以一份未预留木料交换。图纸只学一次，不消耗。
3. 按所需配方准备木料。苔绿色帐布需要从行商处用两份鲜蘑菇换一卷帆布；烧烤网、焖烤罩各需要一套五金包（一根原木换一套），不能凭空获得。石圈利用原本地上的石块重新堆叠，不虚构石材库存。
4. 走到固定操作点后，选择单个部件「开始制作并安装」。在进行中取消、移动、换目标或者存档恢复后不重复扣料；完成时一次性扣库存，写入历史批次投入账本、升级阶段和对应部件可见状态。
5. 火塘重垒石圈后才能造双柱横梁支架。造好支架后，再分别做悬锅吊钩、烧烤网、焖烤烟罩。这三种附件持久保留，却共用 `camp-fire:top` 一个安装槽：装上某一件会自动收起另外两件，已经造好的零件不再支付材料；也可把槽位清空。
6. 木屋已有的「修缮·第一阶段」是屋顶包边、外开窗板、遮雨檐三个外部项目的共同前置条件；它不是一套新房子，也不会偷偷开放室内。

## 代码所有者及存档

- `content/upgrades.ts` 注册永久宿主、子部件 ID、前置关系、材料与可互斥插槽；`content/workshop.ts` 注册装配图纸。
- `content/items.ts` 与 `content/item-types.ts` 注册行商供给的帆布卷、五金包。原料仍遵守既有资源分类，不把「图纸」变成「实体材料」。
- `domain/upgrades.ts` 校验施工资格、一次扣费、逐部件升级账本，以及焚火附件换装；`domain/workshop.ts` 沿已有制作状态和唯一时钟推进并保存 `mounted`。
- `scene/camp-exteriors.ts` 将本项目原创的低多边形几何绑定到已有 THREE 场景根上；静态 clone 的木屋和原篝火状态不变。帐篷改用保留子节点的原 GLB clone，以便局部替换布面；所有新 GPU 资源仍归 `Resources`，没有另建场景或渲染循环。
- `ui/Blueprints.tsx` 展示按宿主分组的可装部件；`ui/Workshop.tsx` 允许行商换材料和图纸；`app/runtime.ts` 统一提交。这轮没有新的存档根字段、在线服务、外部 GLB 或第三方贴图，继续保持世界规则 5。
- 旧 `workshop` 存档缺少 `mounted` 时按空安装位迁移，并补上新的基础图纸；旧客户端不认识新字段时应保护存档而不是覆盖。历史升级账本的原料明细不因后期配方变化而改写。

## 验证重点

领域回归应覆盖：三宿主部件清单及图纸稳定 ID，空材料石圈重垒，前置依赖，库存不足/取消不扣料，帆布和五金的真实商人交易，换装不重扣料，单一上部插槽、读档往返、无效存档保护，以及新外观根节点/可见性/释放。浏览器验收另需观察同一相机与时段的改装前后画面、桌面/手机操作命中和遮挡；自动测试与构建不能代替肉眼核对。

## 继续扩展时的边界

未来可以为每件部件增加第二种款式、耐久或词条，但不把它们揉成宿主的单一线性等级。外观换装可以通过同类互斥插槽延展；结构改造继续使用前置依赖。帐篷内景和木屋室内按照独立私密空间设计，不得在此 PR 里塞入一间不可进入的假房间。
