## 1. 本次范围与状态

本次仅提交方案及 README 入口，不修改源码、运行时参数、存档格式或资产清单，不导入模型、音效，不新建空 service。交付应能指导后续施工者选择同风格动物、配置有限的出场组合，并沿现有架构接入；不以文档提交宣称动物已可见、可互动或已通过性能验收。

动物服务于种林、造景和森林生活，不引入狩猎、战斗、饲养负担或新的强制日常。以后可以接亲近、招手、喂食、鸟屋等能力，但本轮不实现，也不预先开放奖励、制作加速或其他经济效果。既有文档中“完整野生动物/宠物组合属于后续”的阶段边界不变；本文细化下一步方向，不把整份名单变成 M0–M2 的新增必交清单。

需要同时落实三项体验：远处偶见的动物具有体量和辨识度；近处的小动物与现有玩具风角色协调；鸟群、蝴蝶、蛙和夜间叫声让空间有活动，但不把森林填成动物园。

## 2. 动物构成与视觉职责

| 动物 / 组合 | 出场方式与空间 | 资产和动作重点 | 优先级 |
| --- | --- | --- | --- |
| 松鼠 | 高频候选；树干、木桩及树间地面，出现频繁不等于数量多 | 圆润体块、明显尾巴；短跑、停顿、观察或啃食；爬树须有有效宿主挂点 | 第一批核心 |
| 野兔 | 高频候选；草坡、灌木边、家园外围 | 与松鼠同一套比例、材质和细节密度；吃草、停看、短距离跳走 | 与松鼠一起审美术 |
| 母鹿 / 幼鹿 | 中远景溪边和空地，低频；单只或母幼组合 | 可选梅花鹿或白尾鹿方向的小巧鹿型，不把“小型”写成严格物种学分类；同一母幼组合保持物种与造型一致 | 后续鹿组 |
| 大角雄鹿 | 远处林缘、坡顶或空地；稀有的视觉主角 | 体量、抬头姿态和漂亮的分叉鹿角优先；远观也能辨认角的轮廓，不靠毛发细节 | 优先选择一种大型标志动物 |
| 驼鹿方向 | 可替代或后续扩展的大型标志动物，不要求与雄鹿同时制作 | 保留自身厚重体形与掌状角的造型方向；不是小鹿简单放大，也不是其他鹿种的成年变体 | 候选，不增加首批必交量 |
| 白色北美山羊方向 | 高处岩坡、山崖远景，偶尔露面 | 白色体块与山脊形成对比；驻足、转头、少量受控移动；不因此开放高山玩法 | 低频扩展 |
| 狐狸 | 林缘偶尔探头或走过，以傍晚候选为主 | 耳、脸、尾巴有性格，沿用玩具材质；不默认亲近，也不是敌人 | 低频扩展 |
| 小型群鸟 | 中远景树杈停栖、成群飞过或飞离；以群组织 | 麻雀、椋鸟方向可作小型群鸟候选；红雀、乌鸦等作为不同色型/轮廓候选，不要求一次全部制作 | 鸟群批次 |
| 猫头鹰 | 夜间树枝停栖；靠近听觉范围时，间歇叫几声 | 模型与空间音效成套接入；有静默间隔，不持续循环播放 | 夜间批次 |
| 蝴蝶 | 更靠近玩家，花草或溪边局部活动 | 近看可辨的翅形和配色，少量个体组成小簇；不用远景鸟群规则 | 轻量近景点缀 |
| 青蛙 | 河岸有效挂点附近，局部几只 | 简单待机、短跳和间歇蛙鸣；不全图寻路 | 溪边批次 |

鸟的具体物种和音效版本随资产准入确定；尚未选定的名称不先变成正式 `speciesId`。本项目是风格化森林，不以严格复原某一真实地区的完整动物群为目标。

### 同一世界里的 low-poly 与玩具感

远景动物强调轮廓、体量和姿态，可以保留更明显的 low-poly 平面；近景动物强调圆润、亲和和动作节奏。两者共用色板、非金属材质、光照与比例体系，不是两套互不相关的素材风格。

松鼠和野兔应优先来自同一兼容资产系列；来源不同时，先做同框修整样张，再决定采用，不能分别好看就直接混装。狐狸等后续近景动物以这组为参照。近景可以预留探头、伸前爪、回应玩家的玩偶式表现，但这些表现不等于已实现互动。

大型动物不套用小动物的大头短身比例。鹿角、山羊白色轮廓等识别特征应在最低可用 LOD 中保留。距离分层是资产与出场设计，不允许同一动物随缩放从写实模型突然换成另一只玩偶；LOD 只简化自身形状与细节。

## 3. 数量预算：目录可以扩展，活动实例必须有限

区分三个概念：**定义注册**登记有哪些动物；**出场调度**决定本次让谁出现；**表现实例**才占用逻辑、绘制和音频预算。不能把“最多三只动物”实现成目录只能登记三个物种，也不能按物种或分区各给三只。

以下是首轮接入的保守候选值，须在实机验证后冻结。正常目标留有空位，不追求始终填满上限。低性能档可以下调；不能为容纳不合格素材直接提高预算。

| 预算项 | 首轮候选值 | 计数口径 |
| --- | --- | --- |
| 哺乳动物总量 | 常态目标 2，只设一个全局硬上限 3 | 松鼠、兔、狐狸、各类鹿、山羊都计入；远景也不豁免。母鹿和幼鹿算 2 只，不算 1 个免费组合 |
| 同一种哺乳动物 | 默认最多 1 只；兔或母幼组合可显式配置至 2 | 仍受总上限 3 约束；不自动生成同类群落 |
| 大型标志动物 | 同时最多 1 只 | 大角雄鹿、驼鹿、远景山羊等共享出场位；该位是总哺乳动物预算的子约束，不另加额度 |
| 鸟群 / 停栖群 | 同时最多 1 个群组，常态 5–8 只，硬上限 10 | 成员数也受限；一群的停栖与飞行是同一 encounter 的状态，不重复注册两群 |
| 猫头鹰 | 夜间最多 1 只 | 不与默认日间鸟群重叠；鸟类可见总数仍不超过 10，猫头鹰不是免计数装饰 |
| 蝴蝶 | 同时 1 簇，每簇 2–4 只，全局最多 4 | 多个花丛是候选位置，不各自固定生成 4 只 |
| 青蛙 | 同时 1 个河岸小组，每组 1–3 只，全局最多 3 | 多个河岸挂点共用预算，不按每段河岸重复加额度 |
| 动物叫声 | 同时最多 2 个活动声部 | 猫头鹰、鸟鸣、蛙鸣共用动物声部预算；环境底噪另按全场音频预算管理 |

“全局”指当前游戏会话中所有已激活分区的活动实例之和，不是仅计算相机矩形内。离开视野但尚未退出的动物、异步加载预留、退出过渡中的实例都占名额；先回收再激活替代者。远山只留候选锚点，不在每座山后面常驻一套完整 AI。

有效上限同时满足总类、同种、群组成员和标志动物约束。绘制批次或缓存副本不构成新的玩法名额；反过来，一次实例绘制画了十只鸟，也必须记十只成员成本。将来新增宠物时另行讨论预算，不能借“非野生”标签绕开全场性能限制。

## 4. 生境、时段与出场调度

每个出场候选由“定义 + 锚点/路线 + 时段 + 权重 + 冷却 + 预算成本”组成。松鼠、兔较常见；狐狸、鹿和山羊较少；大型标志动物不仅权重低，还要有较长的独立出场间隔。具体秒数、距离与概率待实机调参，不写成已验证数值。

调度先筛合法生境、宿主、时段与可用预算，再用世界 seed、稳定候选 ID 和时间窗口选取组合；不在每帧掷骰子，不因相机转动或模型重载重新抽签。预算不足就跳过候选或等待下一窗口，不累积无限队列。

| 组合配置示例（不是固定物种 ID） | 时段与用途 | 调度规则 |
| --- | --- | --- |
| `birds.day.small` | 白天小型群鸟，远处停栖后飞离 | 群根节点使用一条有效路线，成员使用偏移与相位；不运行十套独立寻路 |
| `birds.dusk.variant` | 傍晚另一种轮廓/色型 | 与白天组互斥替换，上一群释放名额后再进入 |
| `birds.night.owl` | 夜间单只猫头鹰 | 默认不生成夜间小鸟群；模型与音源属于同一 encounter |
| `mammals.common` | 松鼠、兔为主的日常候选 | 按生境竞争共用名额，不保证每次两种都到场 |
| `mammals.landmark` | 鹿或山羊等远景偶遇 | 占一个标志位，也占一个哺乳动物名额；留足静默窗口 |
| `ambient.near` / `ambient.creek` | 蝴蝶小簇 / 河岸蛙组 | 局部挂点轮换，分别受全局物种预算限制 |

时段来自统一时间，不在动物模块里另建“昼夜钟”。当前 `GameState.time` 及 `sceneAppearanceAt(time)` 已提供模拟时间和视觉时刻；完整日历仍是后续能力。本方案兼容另行计划的沙漏 1× / 4× / 12×，不宣称这些倍速已经实现。

倍速影响出场窗口和游戏时间冷却；同一应用主循环提供暂停一致的表现步长，移动、步态和转向需协调过渡，不机械把飞行、振翅、叫声速度放大十二倍。跨过多个窗口时直接重算当前有效候选，不补播所有错过的鸟群和叫声。手动时刻检视不发放资源，也不制造重复实例；正式时间控制的语义由统一时间模块决定。

### 空间与退出规则

地面动物读取既有地表、道路水岸和碰撞事实，不穿屋、越界或走入河心。树上松鼠、停栖鸟和猫头鹰锚点绑定宿主树位及当前代次；树倒、宿主替换或挂点失效时，安排离开或安全取消，不让动物停在空中。

高处山羊可用局部校验过的岩台锚点与短路线，不为此建立全山寻路或开放未经营高山。鸟群路线、停栖点和蝴蝶活动体积同样应避开屋内及明显穿模位置。近、中、远的阈值依据实际世界尺度、相机缩放和屏幕可读性调参。

出场、退出尽量发生在遮挡后或视野外；已经进入近景的动物不能因一个时段边界立即闪退。设计有限退出过渡，并在过渡完成前继续计费。进入/离开距离采用滞回，避免玩家站在边界时不断重建。无合法位置时允许暂时没有动物。

## 5. 注册数据与现有架构接线

下表是**拟议数据契约**，不是声称仓库已有这些类型或文件。实现时可调整名称，但不能混淆定义、布局和运行时身份。

| 数据对象 | 最小字段语义 | 所属层 |
| --- | --- | --- |
| `WildlifeDefinition` | 稳定 `definitionId`；物种/造型族与 `variantId`；哺乳类/鸟/昆虫/两栖类分类；视觉角色；单体/群组；资产、动作、音频配置引用；允许生境；能力声明 | content，只读目录 |
| `WildlifeSchedule` | 稳定 `scheduleId`；候选定义；时段/权重；最短出场间隔；成员数范围；各预算桶成本；目标距离层；首批启用状态 | content，只读规则 |
| `WildlifeAnchor` | 稳定 `anchorId`；区域/生境标签；世界位置或路线；可选宿主树位/代次；地表、停栖或岩台约束 | world，读取统一空间事实 |
| `WildlifeEncounter` | 独立 `encounterId`；定义与锚点引用；生成序号、开始时间和 seed；成员数量；行为阶段；已预留预算；revision | domain，唯一运行时状态 |
| `WildlifeView` | 稳定目标 ID；位置/朝向；语义动作及阶段；显示状态；可用操作和原因；音频提示事件 | domain 派生只读快照，供 scene/UI 消费 |

建议 `encounterId` 使用 `wildlife:` 命名空间，由稳定候选、窗口和生成序号形成，不来自 mesh 名称、数组下标、加载顺序或随机 UUID。一个 encounter 在更换 LOD、重载表现或播放动作时身份不变。鸟群成员主要是该 encounter 内的视觉槽位，不逐只登记成有背包、路径和存档的角色。

注册校验拒绝重复 ID、悬空资产/动作引用、无效时段、负冷却、非法成员范围和预算成本不符。宿主或地表运行时失效则取消该候选，不靠静默改 ID 或重新抽位置补救。未知新增动物定义不会影响旧库存；含持久动物数据时按版本化迁移处理。

| 现有入口 | 已核对的责任 | 动物接入约束 |
| --- | --- | --- |
| `src/app/runtime.ts`、`runtime-loop.ts` | 唯一状态组合与帧调度，暂停/恢复/销毁 | 动物调度和表现由现有循环驱动，不另建 RAF、setInterval 或后台推进 |
| `src/domain/scene-props.ts` | 从现有 time 派生视觉时刻 | 消费同一昼夜结果，避免动物与场景各判断一套夜晚 |
| `src/world/surface.ts` 与现有布局 | 统一地表与空间事实 | 增加轻量动物锚点数据，不复制地形或另造碰撞世界 |
| `src/scene/interaction-registry.ts` | Object3D 映射稳定字符串 ID，并返回注销函数 | 复用身份映射；正式交互时明确目标类型分流，不能把所有动物 ID 交给采集命令 |
| `src/app/player-actions.ts` | 现有玩家动作协调 | 以后互动进入同一互斥、取消与阶段机制，不并行播放第二套玩家动作 |
| `src/scene/resources.ts` 与资产 manifest | 共享资源及其释放责任 | 动物资产进入同一准入、缓存和生命周期体系；具体克隆策略按骨骼/材质验证 |
| `src/app/save-controller.ts`、`world-save-store.ts` | 唯一存档协调与写入 | 实际新增状态时统一版本化接入，不建立 wildlife 专用 localStorage |

第一次实现只建立实际使用的目录、校验、有限状态和表现适配，不预建天气、繁殖、捕食、好感、任务等空模块。文件可按职责拆分，不能把调度、素材加载和模型逻辑全堆进组合根。

## 6. 互动预留：能接线，不制造假功能

**靠近后的观察/警觉/退避**属于动物自主反应；**招手、抚摸、喂食等**属于玩家显式命令。二者分开，不能因为玩家只是经过就消耗物品或强制播放互动。

第一批装饰性动物的玩家能力列表为空，不显示不可用的喂食按钮、不占用 E 键、不挡住树和采集物的点选。动物仍可有稳定 ID，供调度、调试和未来能力挂接；不要求所有可见对象立即加入可点击命中集合。

未来需要互动时按以下契约接通，具体 API 名称届时随既有动作系统确定：

```text
查询：targetRef → 当前支持的 capabilityId、可用性、距离和原因
命令：actionId + actorId + targetRef + capabilityId + expectedRevision
结果：accepted / rejected(reason)，再由统一动作系统推进完成或取消
表现：actionId + actorId + targetRef + motionTag + targetAnchor + phase
```

`targetRef` 至少包含目标类型和稳定 encounter ID；未来具有名字/好感的个体另有持久 ID，不把每次环境刷新当成同一只宠物。`motionTag` 表达“观察、伸手、回应”等动作语义，不暴露某个素材包的骨骼名。人物线负责手臂/身体动作，动物线负责回应，二者共享同一个动作上下文和取消语义。

app 复核目标仍存在、能力已实现、版本/距离/状态合法后才启动。移动、切换目标、宿主失效、目标退出和场景销毁应安全取消；暂停/读档沿用统一机制。后来接入喂食或奖励时，再把库存和结果纳入现有整笔事务，以 actionId 保证幂等；动画完成回调不能直接扣物或发奖。

生境变化、时段变化等由已有世界状态查询或实际需要的事件触发；不预放一排无人使用的 `onWeatherChanged`、`onSeasonChanged` 空回调。鸟屋、灌木、栖息环境影响权重是后续接口方向，不在本轮自动启用生态经济。

## 7. 行为、音效、持久化与释放

行为采用小型有限状态组合即可：待机、觅食、短程移动、观察、警觉、退出。鸟群增加停栖/起飞/飞越/离开，蝴蝶和青蛙采用受限局部运动。只给真正需要的角色执行路径查询；不能借“统一动物 AI”给全部蝴蝶和群鸟添加完整寻路。

猫头鹰先有有效夜间 encounter 和音源锚点，才可发出叫声。统一听觉位置、距离衰减、单只间隔和全局声部预算；鸟鸣、蛙鸣不以“每只一条循环音轨”叠放。模型与音效的许可分别登记。音频未解锁、静音或资源失败时安静降级，不能阻塞游戏；暂停/隐藏停止发出新叫声，恢复不补播积压事件。异步返回已过期的声音直接丢弃。

动物的活动身份、调度和预算由唯一运行时状态源持有；scene 仅持有模型、动画和音源句柄。纯环境动物不保存每一帧位置、每只群鸟的相位；存档只在实际接入时保存必要的调度版本、seed/窗口及需跨读档保留的冷却摘要，再确定性重建。场景重建不能重新抽取当前会话的 encounter，读档不能重置稀有出场间隔。无离线补进度。

有名字、好感或物品结果的动物上线前，另行确定持久身份和迁移策略，纳入完整世界快照；不把环境实例池当作宠物存档。本次文档不增改 `GameState` 或 save schema。

激活先预留名额；加载失败、取消或过期返回都须释放预留且不反复重试刷屏。卸载清理命中映射、监听、动画、音源和实例引用；共享几何/纹理由缓存 owner 释放，不由某只动物销毁公共资源。连续重入、切时段和取消加载都不得泄漏名额或对象。

## 8. 资产选型与场景美术联动

本轮没有核实具体动物包、模型版本或音效文件，**不把此前讨论中的搜索图、素材包名称和许可印象当作已批准来源**。先按 [资产流程](ASSET_PIPELINE.md) 核验具体文件，再在 [资产登记](ASSET_REGISTER.md) 中登记来源、许可、修改与公开再分发条件；不能仅凭网站写“免费”就入库。

动物批次需要同时交模型、必要动作、材质/尺度修整、低细节版本和运行时入口。松鼠/兔先做同框样张；鹿先测远景角形可读性；猫头鹰的模型与音效成套验收。只导入采用的部件，不把整个下载包放进运行时。缺少合格素材时保留未启用条目，不用永久粗占位模型假装美术已完成。

### 从参考场景提取表现方法，而非直接复制整景

已记录的参考方向来自一幅蝴蝶场景中的岩壁、浅色树皮与苔草观感；原图/资产地址、实际树种和许可尚未核实。下面只作为可独立制作的美术目标。若后续取得原素材，仍须重新准入，不能据此宣称已有可拆资源。

| 局部元素 | 希望吸收的表现 | 接入边界 |
| --- | --- | --- |
| 山崖 / 柱状岩壁 | 有方向的竖向柱体、断面分组、清楚的大块明暗，增强岩壁结构感 | 选少量崖面试做，不把全部山体改成柱状；装饰轮廓与可走边界一致，地表事实不分叉 |
| 浅色树皮 | 浅底色上的深色横纹/斑块和有限裂纹，远看仍清楚 | 不未经核实断言参考树就是杨树或白桦；按实际树形选配，保持现有树位、代次与物产身份不变 |
| 草与苔 | 连续地表色块配少量有厚度的草簇/苔垫，近处细、远处简 | 先试地表颜色/低频纹理，再加局部实例；不以满地透明毛片换取细腻感，不整图加密 |
| 近景组合 | 蝴蝶、少量草花、树干和石面的局部关系 | 在玩家会经过或停留的小区域验证，不增加一套独立景观渲染器 |

沿用当前八树形、林下实例与崖壁体系，优先局部替换或改进，不整包覆盖原场景。已有林下数量、批次和三角形上限仍以 [森林形态接入](FOREST_INTEGRATION.md) 和 [PARAMETERS](../PARAMETERS.md) 为准，本方案不批准提高上限。新增树皮材料、草苔和动物还需合计评估绘制调用、骨骼更新、透明覆盖、阴影及倒影开销；“只有三只哺乳动物”不是性能合格证明。

场景美术提升单列工作批次，可与动物分别验收和回退；不把山崖/树皮改造作为注册系统的前置依赖。

## 9. 接入顺序与验收

建议第一批只完成松鼠、兔的统一风格及最小调度闭环，可加一个蝴蝶小簇验证近景。第二批选一种大型标志动物和一个鸟群组合，验证远景、群组及共享预算。再按资产准备情况加入狐狸、山羊、猫头鹰/音效和河岸蛙；母幼鹿与驼鹿变体不要求一起完成。场景美术另批推进。

这是施工顺序建议，不是本次已经执行的工作。每一批均需本游戏实机证据；素材预览、外部演示和构建通过不能替代视觉与行为验收。

| 检查项 | 后续实现应提供的证据 |
| --- | --- |
| 风格 | 松鼠/兔与当前角色同框；远景大鹿角形、山羊轮廓可辨；旋转和缩放无突兀换模 |
| 硬预算 | 多分区、转镜头、加载中、退出中及切时段仍不超过上限；母幼计两只；群组成员成本真实可查 |
| 时间 | 白天/傍晚/夜间互斥组合；暂停和隐藏无推进；倍速接口接通后验证 1×/4×/12×，跨窗不补播 |
| 空间 | 地面/岩台贴合、路线不穿屋；砍树或代次变化后停栖点正确失效；边界无闪现循环 |
| 可扩展接线 | 装饰动物默认无操作且不挡采集；后续真实能力通过同一目标路由和动作协调接入，不重写出场系统 |
| 状态与存档 | 场景重建保留当前调度；读档不重抽稀有出场冷却；未知版本保护原档；没有第二存档写入者 |
| 声音 | 夜间邻近猫头鹰间歇鸣叫，远离衰减；静音/未解锁/失败可继续游戏；不超声部、不补播 |
| 生命周期 | 反复进入、卸载、取消异步加载后，活动实例、预留名额、命中项、音源和缓存引用恢复基线 |
| 性能与降级 | 固定 seed/相机/时间下对照新增前后 CPU/GPU、绘制调用、内存和帧耗时；桌面与真实手机分别记录；降低质量不改玩法身份 |
| 素材授权 | 模型、动画、纹理、音效各自有来源及适合公开入库的许可；修整与导出可追溯 |

运行检查应能查看活动 encounter、各预算桶已用/预留、群成员数、被跳过的原因和声部数；该诊断沿用现有检视入口，不新增常驻 HUD 面板。新增玩法按钮只随实际能力开放。
