# 世界存档

## 当前格式与清洁起点

2026-11-02 经用户明确授权放弃历史试验存档。当前采用世界信封 `schemaVersion: 1`、世界规则 `rulesetVersion: 5`、库存切片 `schemaVersion: 4`。浏览器改用 **`home-of-woods-save-v2`** 数据库，数据库内部版本仍为 1；不读取、不覆盖、不删除旧 `home-of-woods-save-v1` 数据库。默认启动建立新世界，不提供旧试验档自动导入。

旧库存数量表、旧库存格式 1/2/3、世界规则 1/2/3/4 的迁移链和旧运行时补丁已删除。`validateWorldSession()` 只接受当前完整状态；先验证候选，成功后整体应用。测试目录中历史场景证据保留用于验证素材/树位，不再被当成当前存档导入样本。

## 唯一事实源与唯一写入者

`GameState` 持有玩家位置、路径、探索、时钟、采伐、采集、仪式、工作台、库存实例、物理木料岛等现有玩法状态。库存中的家具与其世界位置是同一个实例；仓库木料和物理岛木料互斥。表现层不结算数量，不维护第二份所有权。

`src/domain/world-save.ts` 编码整个世界，库存统一调用 `inventoryPersistenceData()`，包括所有未知附加字段。信封保存布局版本、规则版本、递增序号、保存时间和 SHA-256 checksum。读取先核对原始信封完整性，再验证核心结构和跨切片引用；不能先填默认值再用修改后的内容验证旧 checksum。

可选物品属性的缺省/错误类型/未知枚举由 [物品字段契约](ITEM_DATA_EVOLUTION.md) 处理；有效属性回退不修改原始值，也不会把可写存档变成只读。格式判定只针对核心语义；以后增加稀有度、染色等可选字段不改世界规则号。

## 原子保存、并发与备份

`src/app/world-save-store.ts` 是唯一持久化适配器。数据库 object store 为 `world`，键为 `primary` / `backup`。每次保存先捕获并验证不可变候选，再在单个 readwrite 事务中比较当前主档/备份与预期原值，随后写入新主档和上一份有效主档。事务完成后才报告成功；另一个页面抢先保存会导致比较失败，当前页面不能覆盖赢家。

保存控制器只缓存验证通过的独立副本。活动状态继续推进不改变备份。显式保存、重新读取、导出主档/备份和有效副本恢复继续保留；后台隐藏或销毁也走同一控制器。

## 时间、动作和物理

世界时间只在本地模拟中推进，不补离线收益；沙漏 1×/4×/12× 不改变步行速度。正在进行的制作保留开始时间和身份序号，完成时一次扣料与发放产物；取消不扣料，重复 tick 不再次结算。稀有度在实例生成时确定，与时钟和读档次数无关。

采伐/采集保留资源池、代次、预留、动作阶段和已结算记录，不能因加载模型补满资源。物理岛保存来源批次、姿态、线/角速度、休眠和队列；刚体时间步不乘沙漏倍速，按现有生命周期恢复。

## 保护边界

可解析但不认识的**可选物品属性**被无损保留并使用安全默认表现。核心身份冲突、非法数量、库存与地上所有权冲突、未来核心格式、未知世界布局或 checksum 失败仍进入保护，不凭空修复资产。有效副本恢复是显式操作；存储失败保留上一份有效数据。

当前未实现任意损坏条目的隔离恢复，也未实现跨浏览器/跨域导入。此限制不影响可选物品字段的日常扩展。

## 验证

领域/控制器测试覆盖世界往返、当前动作恢复、原子保存、备份、并发和失败保护。字段扩展与稀有度的本轮证据见 [ITEM_RARITY_VERIFICATION.md](ITEM_RARITY_VERIFICATION.md)；旧阶段的不可变证据不改写。

## 动物临时状态

最终动物整合不升级世界规则或库存格式。`wildlife` 仅允许存在于运行态，序列化时剔除；读档先清除旧会话动物，再按保存的时间／seed 重建候选。动物不生成库存收益。库存统一 `inventoryPersistenceData()` 编码和 Woodcraft 所有权校验保持不变，组合往返测试见 `tests/final-integration.test.ts`。
