# 世界存档

天气回接新增可选 weather 切片，保存模式、强度、自动序列起点、最后结算时刻以及湿地、积水和积雪。当前存档缺字段时在原游戏时间初始化。木料 woodCondition 保存湿度与表面积雪，持续变化保持 stackKey 稳定，收回时按数量加权混合或生成独立 woodLot。工作任务保存开工所用 woodMoisture 与实际工时，天气配置变化可触发原 checkpoint。仍由 save-controller 与 world-save-store 协调写入。当前验证见 [天气回接记录](scopes/running-selection-weather.md)。

2026-11-05 营地生活回接继续使用主体 `home-of-woods-save-v2`，不读取沙盒数据库。装配、有限叶堆与原物使用频率进入同一世界记录；短动作事件不因加载而重播。当前合同与验证见 [CAMP_LIFE_INTEGRATION](CAMP_LIFE_INTEGRATION.md)。

## 当前格式与清洁起点

独立附件的归属见 [道具去向与宿主关系](ITEM_DESTINATIONS.md)。与施工阶段的 `workshop.mounted` 不同，独立附件只在 `inventory.instances[].location` 的 `mounted(hostId,slotId)` 记录所属宿主；冲突槽位、缺失宿主及自引用/环路会保护存档，不自动迁回背包。


当前世界信封仍为 `schemaVersion: 1`，世界规则已演进至 **`rulesetVersion: 9`**、库存切片至 **`schemaVersion: 6`**，使用同一个 **`home-of-woods-save-v2`** 数据库（数据库内部版本仍为 1）。2026-11-02 的清洁起点原为规则 5 / 库存 4；后续材料运输引入规则 6 / 库存 5，独立道具安装归属再引入规则 7 / 库存 6；行商账本已使用规则 8，营地生活及天气回接沿用这一基线；东岸扩区以规则 9 注册新增区域和桥梁，库存格式保持 6。原 v1 试验数据库仍不读取、不覆盖、不删除；世界规则 1–4 与库存格式 1–3 不导入。本次扩区直接接受旧固定山谷布局的规则 8，补齐东岸后迁入；其他布局/规则组合以解析器的明确白名单为准。库存 4、5 的有效记录仍按已定义路径迁入，带新 `mounted` 位置却伪称旧版本的记录必须保护。

旧库存数量表、旧库存格式 1/2/3、世界规则 1/2/3/4 的迁移链和旧运行时补丁已删除。`validateWorldSession()` 只接受当前完整状态；先验证候选，成功后整体应用。测试目录中历史场景证据保留用于验证素材/树位，不再被当成当前存档导入样本。

## 唯一事实源与唯一写入者

`GameState` 持有玩家位置、路径、探索、时钟、采伐、采集、仪式、工作台、库存实例、物理木料岛等现有玩法状态。库存中的家具与其世界位置是同一个实例；仓库木料和物理岛木料互斥。表现层不结算数量，不维护第二份所有权。

`src/domain/world-save.ts` 编码整个世界，库存统一调用 `inventoryPersistenceData()`，包括所有未知附加字段。信封保存布局版本、规则版本、递增序号、保存时间和 SHA-256 checksum。读取先核对原始信封完整性，再验证核心结构和跨切片引用；不能先填默认值再用修改后的内容验证旧 checksum。

可选物品属性的缺省/错误类型/未知枚举由 [物品字段契约](ITEM_DATA_EVOLUTION.md) 处理；有效属性回退不修改原始值，也不会把可写存档变成只读。格式判定只针对核心语义；以后增加稀有度、染色等可选字段不改世界规则号。

## 原子保存、并发与备份

`src/app/world-save-store.ts` 是唯一持久化适配器。数据库 object store 为 `world`，键为 `primary` / `backup`。每次保存先捕获并验证不可变候选，再在单个 readwrite 事务中比较当前主档/备份与预期原值，随后写入新主档和上一份有效主档。事务完成后才报告成功；另一个页面抢先保存会导致比较失败，当前页面不能覆盖赢家。

保存控制器只缓存验证通过的独立副本。活动状态继续推进不改变备份。显式保存、重新读取、导出主档/备份和有效副本恢复继续保留；后台隐藏或销毁也走同一控制器。

## 时间、动作和物理

世界时间只在本地模拟中推进，不补离线收益；沙漏 1×/4×/12× 不改变步行速度。正在进行的制作保留开始时间和身份序号，完成时一次扣料与发放产物；取消不扣料，重复 tick 不再次结算。稀有度在实例生成时确定，与时钟和读档次数无关。

采伐/采集保留资源池、代次、预留、动作阶段和已结算记录，不能因加载模型补满资源。物理岛保存来源批次、姿态、线/角速度、休眠和队列；刚体时间步不乘沙漏倍速，按现有生命周期恢复。

## 保护边界

可解析但不认识的**可选物品属性**被无损保留并使用安全默认表现。核心身份冲突、非法数量、库存与地上所有权冲突、未来核心格式、未知世界布局或 checksum 失败仍进入保护，不凭空修复资产。有效副本恢复是显式操作；存储失败保留上一份有效数据。

当前未实现任意损坏条目的隔离恢复，也未实现跨浏览器/跨域导入。此限制不影响可选物品字段的日常扩展。

## 验证

领域/控制器测试覆盖世界往返、当前动作恢复、原子保存、备份、并发和失败保护。字段扩展与稀有度的本轮证据见 [ITEM_RARITY_VERIFICATION.md](ITEM_RARITY_VERIFICATION.md)；旧阶段的不可变证据不改写。

## 动物临时状态

最终动物整合不升级世界规则或库存格式。`wildlife` 仅允许存在于运行态，序列化时剔除；读档先清除旧会话动物，再按保存的时间／seed 重建候选。动物不生成库存收益。库存统一 `inventoryPersistenceData()` 编码和 Woodcraft 所有权校验保持不变，组合往返测试见 `tests/final-integration.test.ts`。

## 修缮进度的兼容扩展

本次在 `workshop` 切片内新增 `upgrades`，继续使用规则 5、库存格式 4 和现有数据库。读取本字段加入前的有效规则 5 存档时，先按原始字节验证 checksum，再补空升级账本与营地自带的木屋首阶段图纸；原图纸、物品和库存不重置。这不重新开放规则 1–4 的旧试验档迁移。

升级账本以目标稳定 ID 为键，保存级别、已完成路径 ID、实际投入材料批次和完成时间。实际投入是历史事实，后续调整配方成本不改写旧账本。修缮复用 `workshop.job` 的任务序号、开始时间和唯一时钟，任务额外记录目标、路径与图纸；材料只在完成事务中扣除。重载后从保存进度继续，完成阶段和扣料一起提交。

校验拒绝路径顺序与级别冲突、重复阶段、缺失投入记录、未来完成时间和动作目标冲突；未来可识别结构的未知目标账本仍保留。测试覆盖旧规则 5 补字段、修缮中/后往返和损坏保护，见 `tests/upgrades.test.ts`。

## 营地生活记录与表现边界（2026-11-05）

`workshop.job.assembly` 保存几何、工序、已卡位件和当前试放；`workshop.sweptLeaves` 保存三处有限叶堆。扫帚 `broomUsage` 与原碗 `mealUse` 随同一实例保存使用/触发频率，装卸、摆收和神谕不复制实例。用餐、重活资格及逐日限次在 06:00 换生活日，仍只有一份世界时间。

重新读取/恢复有效副本成功替换世界后，app 清理本会话的用餐和扫帚事件去重历史，以允许恢复前的合法同序号新提交；加载本身不生成动画事件，普通取消也不清除去重。阅读/进食只借座点，保存的玩家仍在合法站位。开始摆放先释放旧持物/坐姿并零步渲染，不改已经结算的饭或叶堆。

稀有度偏好继续用 `home-of-woods.rarity-vfx`，新奇趣偏好用 `home-of-woods.whimsy`，两者只存显示选择，不作为库存/世界的第二个写入者。

## 东岸扩区

东岸布局与规则版本以 `src/content/world.ts` 的当前登记为准。桥梁继续保存在 workshop.upgrades，东岸树木和采集来源进入原有 forestry / gathering；探索通过 visited 保存，未交付木料的来源随 inventory 栈保存，没有第二套区域存档。

扩区适配仅补齐旧固定山谷缺少的东岸记录及基础桥梁图纸，保留原营地、位置、库存、天气湿度和树木状态；先验证原摘要，再补齐并执行统一校验。当前接受的布局与规则版本由解析器明确列出；未知布局与未来格式仍由原存档边界处理，本轮不建立通用历史迁移框架。
