# 林间行商 · NPC 与交易系统（PR #16）

这是一名偶尔到访的外来商人，而非固定村庄商店；主题仍是独居林场。行商在远处出现，沿临时路径来到营地，赶一头驴与一辆有布篷的木车；离开时沿原路退出。**不因本 PR 冻结整个日历、节律或离线时间规则**。

## 实体与素材

- 人物复用已接入的 KayKit CC0 `visitor.glb` 和 `motions.glb`，保持与玩家同一比例、骨架与材质风格；独立的 `scene/characters.ts` 从世界时钟取样，在靠近时挥手、行进时播放行走动作
- 首版车厢由 `scene/merchant-wagon.ts` 的本地程序网格形成：四轮、封闭布篷、低侧板、牵引杆及小驴。尺寸/颜色跟现有游戏保持一致，货厢没有动态堆放的模型，也没有外部运行时请求
- 外观参考 [Codels Covered Wagon](https://codels.download/models/wagon) 的 CC0 低模构思；**没有复制该资源的二进制或源代码，当前车为项目原创程序几何**。未来可换成实际审过许可的 GLB，不改变领域逻辑。现有 KayKit 角色许可见 [资产登记](ASSET_REGISTER.md)
- 选中命中、路边到访位置在现有场景里登记；表现不拥有铜币、商品、时间和库存的结算

## 物品/钱/图纸的唯一事实

| 事实 | 数据入口 | 不变量 |
| --- | --- | --- |
| 铜币、赊账、收购预算、剩余车厢、交易历史 | `GameState.merchant` | 金额均为非负整数；每笔交易整体成功或整体失败 |
| 可堆叠的干粮、帆布、五金、肥皂、浴盐、纸墨和烟花 | `ITEM_CATALOG.items` → `inventory.stacks` | 取得真实物料，不自动触发尚未开发的消耗效果 |
| 桌椅、木作等完成品 | 现有 `inventory.instances` | 出售必须是仓库内的真实实例；按实例 ID 移出，任何品质/词条不能重卖 |
| 永久习得的基础图纸 | `workshop.blueprints` | 学会一次永久可用，已学图纸再次购买被拒绝 |
| 有限次数的复杂图纸副本 | `inventory.instances` 中的 `blueprint.sheet` | 副本有独立实例编号、来源图纸和余次；制作或升级**成功结算**后才扣 1 次；查看、取消、走近不扣 |

图纸的永久性、复杂度使用次数与抽出的成品稀有度是**独立维度**；制作概率沿用 [参数化图纸](PARAMETRIC_CRAFTING.md)，不重新投掷已生成物的品质。

## 首版交易流程

走近停稳的行商 → 选购或选卖 → 一张净额账单 → 确认后更新存档与库存。远处可见但不得交易；进行中的砍伐、采集、祈祷和工坊动作不可同时发生交易。

- 固定保障：每次一袋常备粮；首次可领取见面礼（粮袋、基础木作图纸）。粮袋可有限赊账，其他货物必须支付铜币；卖出所得先还旧账
- 货单：固定物资＋随到访批次改变的部分图纸与日用品，`merchantListings(seed, visitIndex)` 确定。打开/关闭面板与沙漏倍速不刷货
- 收购：预算、车厢容量、单个成品类型的收购数量三道独立门槛。普通木墩已开放；大桌子、木椅和小木雕仅注册为未来条目，不伪装成现有可交易物品
- 货币名称固定为**铜币**，由整数字段计价，不是可拾取/运输的物理堆叠物
- 外部交易记录 `merchant.receipts` 只保留有限最近记录用于诊断；不凭收据重复补发奖励，不生成 NPC 的第二个可写物品库存
- 数值（800 收购预算、100 车厢格、200 赊账上限）是初始可调平衡数，不代表世界价格规则已冻结

## 游戏 UI

行商是一张图标化货箱面板：**买入/卖出**切换、商品分类图标、选中物品局部说明、铜币/预算/运力，以及底部单行净额结算。规则藏在 `?`；仓库与图纸的长解释折叠成详情。不把全部解释文字铺在游戏画面里。移动端网格减到三列，不独立开发网页版商城。

## 节律与未来

`content/merchant.ts` 的 `MERCHANT_VISIT` 只是一处临时参数；第一次来得较早，后续低频到访。另一条时间机制专题将统一决定来访频率、到访时长、加速沙漏及玩家错过访客的规则。这里不铺设大段道路，不增加其他 NPC/市场，也不加完整商品供需模拟。

## 验证约束

`tests/merchant.test.ts` 检查未走近拒绝、首次礼物不能重复、铜币结算、真实入库出库、粮袋赊账/还账、同类收购上限与原子失败、图纸成功制作才磨损、永久知识不磨损、世界存档 8 和规则 7 的迁移。其他回归测试继续覆盖物品批次、负重、安装、动作和场景。

此 PR 的 `npm run check` / CI 通过是代码与领域验收的一环，**不等于**已经做过人工实机美术、手机触摸和长时间来访节奏验收；这些没有验证前不得宣称完成。
