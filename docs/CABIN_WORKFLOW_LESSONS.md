# 木屋两期尝试复盘：先规划需求，再决定制作流程

日期：2026-11-12。本文记录木屋任务前期生成/拼接尝试，以及后续 World Labs 原生建模与游戏接入两期的流程教训。当前产物明确为**未完成灰盒，基本可作为错误流程的反例**。本文入库不代表木屋交付，也不授权恢复施工。

## 共同问题：没有把游戏目标转成制作依据

目标是在既有森林生活游戏中，得到陈设完整、角色能够使用、与营地连续衔接的小木屋。实际执行却逐渐围绕工具调用、导出格式、面数统计和局部检查展开。工具步骤完成了，游戏需要的空间、观感和使用流程没有同步成立。

第一步应依据整体游戏目标和当前 scope 定义交互：玩家在哪些地方会实质触及，哪些物体需要拿取、开合、坐卧、放置，哪些空间需要走入、绕行和碰撞，哪些部分只有观看需求。由这些需求决定几何、材质、碰撞、分件及状态归属，不能先造一个房间，再设法给它补用途。

交互定义必须先于建模。最后接交互，指实现已经定义好的行为和主线接线，不是最后才考虑玩家怎么使用。

## 两期各自暴露的问题

| 阶段 | 具体失误 | 应改变的决策 |
| --- | --- | --- |
| 前期生成与空间尝试 | 没有先把官网现成小房间范例的可用流程核实清楚，就扩大尝试；反复得到空屋、屋外内容或无法直接接入的整景，把参考图、API成功和导出当作推进成果。 | 先用最小、有代表性的完整室内验证路线。确认家具、导出、分件和游戏使用限制，再决定是否投入；空房不进入下一步，不做本次不需要的屋外场景。 |
| 前期工具与费用决策 | 没有先区分Studio与开发者接口的权限和计费，把接口报错直接归因到账户；未先核价启动高成本任务，追加任务延迟结算又超出约定上限。 | 调用前明确产品入口、输入、输出、成本与停止条件；余额不等于采购或续跑授权。费用不明确就不启动，失败不能自动转成下一轮付费修补。 |
| 后续原生建模 | 得到基础形体后，材质和整体观感仍未成立，就转向参数变体、支撑数量、容器、存档等接线；模型停留在灰盒，却被几何准入措辞抬高了状态。 | 先按已定义的交互需求完成结构和可用空间，再完成材质及实际游戏镜头中的观感。视觉未成立时不扩展工程面。 |
| 后续面数处理 | 把固定围护2,000面的上限当作压缩目标；屋顶仍占744面，未逐项说明其轮廓价值。用整包17,008面统计代替当前画面完成度判断。 | 上限不是要用满。简单墙体先以最少必要面做对厚度、洞口和轮廓；木纹与表面细节主要交给材质，不保留无用途的导出分段和倒角。 |
| 后续空间与接线 | 入口存在约44厘米真实空缝，却先用跨缝支撑计算保证可走；床的寻路终点与休息资格不是同一组位置；长凳前方净空不足；出门镜头跳到山谷远景。 | 尺寸、净空、角色包络和接近点在设计时就要统一。可走的算法结果不等于真实接地；按钮可点不等于完整使用；同一引擎运行不等于无缝衔接。 |
| 两期的验收组织 | 独立检查不断发现问题，却未阻止下一步扩大施工；边改边验，热更新反复打断操作，局部通过积累成了虚假的进度感。 | 监理应在扩展前判断是否值得继续，而非事后不断补审计。每轮只解决一个明确失败，冻结版本后连续操作；未过关就不晋级。 |

## 正确的规划与推进顺序

1. **定义整体目标和本次可玩范围。** 写清游戏阶段、时代/用品限制、玩家要完成的生活行为、交付画面，以及本次不涉及的内容。阶段规划不能自动变成本轮全部施工范围。
2. **划分实质触及、3D交互与纯视觉需求。** 对每个区域和物件明确用途、可达性、真实尺寸、操作空间、视角和状态归属。不可使用的空间不按完整可交互空间堆几何；纯视觉部分仍有表现需求，但只保留实际镜头、轮廓、遮挡和光影需要的几何。
3. **据此选资源和工具路线。** 先找可复用范例、参考图和现成资源，核实许可与实际导出能力，再决定是否生成或原生建模。工具服务交付，不以“已经调用某API”证明路线正确。
4. **用最少必要几何做对结构。** 先把门洞、地板、围护、家具承托和所需通道做对。面数预算是约束，不是工作量目标。没有实际用途的内部空间和细分不值得建；不靠缩人物、隐形坡或借面算法掩盖可见错误。
5. **完成材质与整体观感。** 在实际游戏镜头、角色尺度、白昼与夜间条件下看房间，确认木材、布料、轮廓、色彩、照明与遮挡。几何、法向、闭合和面数检查仅证明相应技术条件，不证明资产完成。
6. **实现已定义的交互，先完成一个最小闭环。** 原角色从营地进屋、绕过家具、使用一个核心物件、出屋继续游戏；复用原状态与保存机制。沙盒可以隔离运行，但空间、身份和接入接口应在设计阶段想清楚，不能最后才发现与主线接不上。
7. **冻结后验收，再决定扩展。** 先检查连续操作、画面和针对性的性能，再扩到其它家具与参数变体。独立监理对具体失败给出明确结论，不用报告数量代替解决问题，不在同一验收过程中持续改源码。

## 如何判断完成与停止

“参考成立”“工具成功”“几何检查通过”“局部交互可用”“完整游戏交付”是不同状态，不能互相替代。床或木箱单项通过，可以记录该事实；材质未完成、出门镜头错误或空间仍有glitch时，整体仍是未完成候选。

路线在完整室内、预算、原生资产可用性或主线衔接上失败时，应停下来重新判断方案，而不是持续付费追补、增加工程接口或扩大审计。应优先保住用户的时间和预算，不以既有投入为继续投入的理由。
