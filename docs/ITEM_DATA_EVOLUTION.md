# 物品字段扩展契约

2026-11-02 重构：用户明确允许放弃所有试验历史存档。以下规则替代之前的逐版本库存迁移方案；旧方案仅保留在 Git 历史中。

## 核心身份严格，附加属性开放

库存采用当前核心格式 `schemaVersion: 6`。材料批次新增核心位置 `transport`（缺省为营地；另有随身和地面位置），根记录 `carryMode` 保存携带方式。原有材料搬运迁移保留（库存 4 / 世界规则 5）；新增独立道具安装归属从库存 5 / 世界规则 6 明确迁移为库存 6 / 世界规则 7。此前库存 4 / 世界规则 5 的原库存仍在营地，原数量和扩展属性不变；与新保留字段重名的旧数据保护原档。更早的废弃试验格式不恢复。详见 [材料负重与搬运](CARRYING.md)。

批次核心是 `itemId`、`qualityId`、`quantity`，实例核心是 `instanceId`、`definitionId`、`blueprintId`、`createdAt`、`location`。 `location` 目前包括 `inventory`、`world` 与新增的 `mounted(hostId,slotId)` 三种互斥归属。宿主不保存第二份道具副本；安装关系的引用、互斥、兼容和环路在统一库存边界检查。参见 [独立道具去向与宿主关系](ITEM_DESTINATIONS.md)。身份、整数数量、位置与所有权不变量继续校验；未知物品 ID 仍可保存，不强制套用当前目录定义。

物品记录、批次木料规格和库存根记录允许额外的 JSON 字段。读取时不再用完整键名清单拒绝新增字段，也不按旧清单重建一个缩水对象。JSON 校验只排除不可序列化值、循环、访问器、非有限数字和过深/过大的数据；不把未知属性当作格式错误。`quantity`、`delta`、`revision` 等操作字段仍有明确保留用途。

## 原始数据与有效属性分开

`src/domain/item-properties.ts` 的 `ITEM_FIELDS` 集中声明字段验证器和稳定缺省值。业务和 UI 通过 `itemProperties()` / `itemRarity()` 读取有效属性，不直接把未经解析的可选字段用于运算。

| 原始情况 | 本版本使用的值 | 写回规则 |
| --- | --- | --- |
| 缺少 `rarityId` | 普通 | 不强制补写，不发警告 |
| `rarityId: 'epic'` | 史诗 | 保留 |
| 合法 JSON 但类型错误，如 `42` | 普通 | 原值保留，IO 边界产生诊断，不阻塞世界 |
| 当前不认识的等级字符串 | 普通表现 | 保留字符串，不永久降级 |
| 未注册的新字段 | 当前逻辑不使用 | 按原值往返保存 |
| 缺少或非法词条数组 | 空词条 | 原始值保留；有效的未知词条 ID 不删除 |

缺省规则不等于生成规则。历史缺省解释必须稳定；新物品在生成时明确写入其确定等级。修改图纸或生成权重，不能重新抽取已有实例。新增染色等可安全缺省字段，只需增加字段定义和实际消费者，不修改库存或世界 codec，不提高核心格式版本。

参数化制作物现在可选保存 `geometry: {templateId, version, family, parameters}` 与 `crafting` 来源/评分信息。未参与参数化装配的物品完全可以没有这些字段；普通木墩采用预设中性评分，不能伪称玩家已进行了手工校准。完成品不保存临时物理散件。旧/未知生成器版本必须保留原始 JSON，渲染侧不得用最新默认值悄悄改写；见 [参数化图纸契约](PARAMETRIC_CRAFTING.md)。

## 所有修改必须无损保留扩展

库存事务只替换数量；摆放和收回只替换位置核心；原料从仓库进入 Woodcraft 物理岛再收回，保留完整来源批次。未参与本次操作的字段不能丢失，包括实例和位置上的未知 JSON 元数据。

堆叠身份由全部非数量属性的规范化 JSON 决定；对象键顺序不影响身份。属性不同的物品不自动合堆，哪怕当前代码不认识差异。调用扣料事务时应携带被选中批次的完整身份，不能仅凭名称/目录 ID 扣减具有不同属性的批次。制作、加工产生的是新物品；产物属性由生成规则决定，不等于无条件复制投入属性。

`inventoryPersistenceData()` 是库存持久化切片的唯一编码入口，供世界存档与切片测试共同使用。不存在第二份 localStorage 库存。

独立持有、可拆装的道具定义现通过同一个 `ITEM_CATALOG.ownedItems` 注册索引，与堆叠类 `ITEM_CATALOG.items` 共用稳定 ID 空间。候选门铃/纸条箱/铜壶仅登记为计划态，不暗含已获图纸、词条效果或模型。原有 `workshop.mounted` 仍服务于固定设施升级，不能把它与实例 `location.kind='mounted'` 当作重复所有权记录。

## 什么仍需要版本变更

新增可选属性和目录定义不需要迁移。只有核心语义发生不兼容变化，例如计量单位、所有权结构、实例身份体系改变，才提高核心版本并明确决定迁移或重置。数量损坏、身份重复、所有权冲突和完整性校验失败不能靠填默认值掩盖；当前保留整档保护和有效备份恢复，不声称实现任意坏档的逐条隔离恢复。
