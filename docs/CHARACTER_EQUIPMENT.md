# KayKit 模块化衣装：实现范围与「衣」类词条边界

状态：2026-11-04，PR #17 的角色装备技术底座；**非已开放装备经济**。基于已接入的 KayKit 23 骨 Rogue 与现有 Three.js 场景实现，不覆盖原角色 GLB、不引入新素材授权和第二个动画时钟。

## 两个层次，不混为一谈

1. **外观与装配（已实现可检视）**：现有玩家模型保持默认。通过 `?inspect=1` →「运行检查」→「人物衣装检视」能够分别选择发型、上衣、裤装、鞋靴、帽子、背包，在角色近景切换，并可恢复原造型。这是 **QA/美术检视**，不产生衣服、图纸、仓库实例、制作成本或存档变化。
2. **真实物品穿戴（数据契约已具备，玩法尚未开放）**：角色 `player` 作为 `character` 宿主，共用 `inventory.instances` 唯一所有权。头、上身、下身、脚、背和左右手装备槽依旧 `planned`，旅行帽和背包也为 `planned`。以后从图纸获得并完成装卸事务后，挂到头/背的真实实例已有相应外观适配；实际制作入口、UI、NPC 商店库存、装备收益都仍未实现。仅仅在检视器里戴帽或背包不授予装备能力。

## 已支持的视觉模块与边界

| 模块 | 现在可见的选择 | 实现方式 | 能支持的词条方向 | 暂不支持 |
| --- | --- | --- | --- | --- |
| 发型 | 原发型、短发、侧分、盘发、马尾 | 头骨骼上的独立低面数网格；马尾可轻微摆动 | 发色/造型、小幅装饰动画 | 真正连续长发物理、复杂编发、风吹整头发 |
| 上衣 | 原工作服、田野衬衣、帆布背心、劳动外套 | 胸、上臂、前臂独立外覆部件，随现有骨骼运动 | 配色、袖口/衣扣/小徽饰、1–2 处轻量动态 | 任意服装曲面、布料折叠、收紧袖筒、完全防穿模 |
| 裤装 | 原长裤、林地长裤、补丁工裤 | 骨盆/大腿/小腿分段外覆；膝盖随腿骨转动 | 配色、护膝、补丁/口袋小动作 | 宽松裤腿布料模拟、跨骨骼连续裙摆 |
| 鞋靴 | 原鞋、低帮鞋、高帮工作靴 | 脚与小腿挂点；靴筒随小腿 | 外观变化、泥点/足迹（需地表事件服务） | 鞋底受力变形、复杂鞋带/逐趾动画 |
| 帽子 | 无、草帽、布帽、毛线帽 | 跟随头骨骼的刚性部件 | 轻量饰物、天气响应（需天气事件） | 真实帽檐布料和流体，自动适配所有发型形体 |
| 背包 | 无、帆布背包 | 胸背骨骼刚性挂件，预留 bow-left/bow-right 两个锚点（默认不摆动） | 获得对应词条后再启用蝴蝶结局部摆动、外观等级差异 | 在没获得背包情况下增加负重；自动计算包内具体货物的变形与碰撞 |

本轮服装**不是真正重新裁剪的完整蒙皮服装网格**：为了保留原人物和双手挥斧接触，采用覆盖在原模型外侧的分段几何。它能跟随基础肢体运动，却不应被描述为精细的 SkinnedMesh 衣料或通用角色换皮流水线。各模块名/材质是原创的简易几何示例，风格为朴素森林工作服，不包含奇幻铠甲或仙侠饰件。所有部件的显隐由同一场景 Resources 管理，正常人物与动作过程中的 `createActor` 第二套骨架都附着同一个外观选择，避免采集/祈愿时突然失去装备。

## 技术边界和词条策划判准

- **基本稳定的触发接口**：`equipped`、`movement`、`action` 与宿主提供的 `weather`、`terrain`、`carrying` 语义上下文可以作为将来词条定义的输入；但语义上下文存在不等于已有天气、脚印、保暖或搬运收益 handler。
- **目前确实能看见的表现**：换部件、部分配色方案、单个骨骼的刚性挂件、上下肢随动，以及马尾的轻量摆动；背包两翼局部摆动仅为计划态词条锚点。原有 `item-local-motion` 支持对一个道具最多两个命名子节点的确定性运动，但当前旅行系列的词条模板仍 `planned`，与真实物品装卸和效果服务未接线。
- **合理作为近期词条候选**：帽徽微动、头发轻摇、获得对应词条后的背包饰件轻摆、口袋里偶尔露出叶片、裤腿表面的泥点、外套褶边颜色随光线略变。需要给特定道具增设锚点/贴图时必须先建模，不能单靠 data ID 变出几何。
- **需系统前置后再考虑**：雨天防护、温度/体力修正、背包承载力、地面足迹、与动物的互动、行商注意装束等。需相应天气、体能、物流、地表或 NPC 业务事件，并明确经济/表现区别；不得从装备视觉状态直接推导收益。
- **不按首版支持设计**：可解算布料、长发摆荡、自定义裙子/披风与大量关节、真实全身物理碰撞、高精度自动叠穿、自由捏脸、完整时装商城、跨人物任意骨架换装。它们需要新资产/动画/求解器，不能当作免费词条效果。

## 验收方式与尚未完成的实际视觉复核

自动测试使用实际已经提交的 KayKit GLB，检查骨骼锚点、换装选项、双骨架外观同步、穿戴实例属性不被表现层改写、复位与释放。此前采伐/采集真实 GLB 接触测试依旧执行；GitHub CI 的 `npm test`、`npm run check`、`npm run build` 是工程门槛。

**还需做的视觉验收**：浏览器在人物前后侧、砍树、拾取、低头、抬手等姿态观察网格交错与遮挡，手机近景视口检查帽子/背包是否超出镜头。自动通过不能替代对实际画风与穿模的观察。未通过视觉验收前，服装仍应以「结构可切换、造型待精修」标记，不合并成正式可制作衣物。

程序入口：`src/content/wardrobe.ts`、`src/scene/character-wardrobe.ts`、`src/scene/characters.ts` 与 `src/ui/WardrobeLab.tsx`；数据归属见 [独立道具与宿主关系](ITEM_DESTINATIONS.md)。
