# 三类林地代表样区

日期：2026-11-19。状态：三片林地是未来正式游戏模块，当前通过独立入口运行；共用照度与阴影已接入，构建与定向测试通过，真实 3D 画面尚未验收。原始交付见 [扩图范围](scopes/forest-biome-expeditions.md)，本轮变化见 [共用照明接入](scopes/forest-lighting-integration.md)。

入口为 `/sandbox/forest-expedition/`，开发时运行 `npm run dev:forest`。路径暂沿用原名，本模块持续面向正式扩图维护，不按历史沙盒冻结。从营地向上、沿山腰和向下的三个方向，分别承接林相、路线、资源和返程。当前使用地点按钮切换，尚未接入主营地的跨图转场、开放条件或主存档。

## 三张地图现在提供什么

每张范围为 180 × 180 游戏单位，固定 seed，包含一个主回路、两条支路、四种局部生境、两处地标和十二个资源点。人物全高约 2 单位；尺寸是游戏设计输入，不是现实样地测量。

| 地图 | 四种局部生境 | 树形与尺度 | 主要活动 |
| --- | --- | --- | --- |
| `upper` · 雾杉高林 | 巨木厅、苔藓溪沟、风倒林隙、露岩肩坡 | 针叶主林冠 24 / 30 / 36 单位；肩坡松、冷杉 18 / 22 / 26；两棵地标 48、40，约 24、20 个人高 | 土生菌、木生菌、树脂、种源、枝料；两处有限长材回收点 |
| `mixed` · 斑荫横岭 | 松栎肩坡、老枫凹谷、桦杨新林、向阳果丛 | 普通乔木 12 / 16 / 20；横枝老枫 25，岩肩双干松 23；干湿坡与林缘分群 | 菌类、树脂、弯曲枝料、果子、榛果、种源；一处长材回收点 |
| `lower` · 白桦溪甸 | 桦杨亮林、枫榆阔冠、白蜡河岸、榛果林缘 | 普通乔木 10 / 14 / 18；溪甸伞榆 23，三生白桦 19；多干灌丛 2.4 / 3.2 / 4 | 菌类、坚果、果子、树液、种源与枝料；一处长材回收点 |

数据定义见 [林地目录](../src/content/forest-expedition.ts)，实例与地形生成见 [布局模块](../src/world/forest-expedition.ts)。树木按生境权重、稳定变体与少数尺寸档分群，主路、支路、补给点和资源接近处留出净空。道路不要求穿越深水；岸边可达性、树干与较大根肋碰撞使用同一组通行检查。

### 生态依据与美术取舍

上坡的湿润高林借鉴 Olympic 的**温带雨林**：大针叶树、附生苔藓和蕨、缓慢腐朽的倒木与倒木育苗构成林相线索。它不是高山寒带森林的完整重建；“向上”表达相对营地的出行方向，不把海拔本身当成巨木和湿润环境的充分原因。参见 [NPS · Temperate Rain Forests](https://www.nps.gov/olym/learn/nature/temperate-rain-forests.htm)。

横坡与下坡借鉴北方针阔过渡、干湿地形和扰动后更新的差别。Acadia 位于东部落叶林与北方针叶林的交界，其针叶与栎、枫、山毛榉、桦等组合提供形态参照；本游戏把这些线索组织为更容易辨认和游玩的生境。参见 [NPS · Forests](https://www.nps.gov/acad/learn/nature/forests.htm)。

三图属于混合虚构生态。`redwood`、`hemlock` 等键首先约定造型家族；红杉式巨干与 Olympic 式苔谷组合，不声称红杉就是 Olympic 的典型树种，也不把北美东西岸树种名单当成同一处真实群落。没有逐片树叶：辨识主要来自主干比例、分叉层级、冠团分布、白干、横枝、根盘和苔帘。两篇网页只作为生态说明参考，未下载或分发其照片、地图或模型。

## 可以连续完成的玩法

点击物产先查看；远处提供“走近”，到达后明确采集。角色沿可走地表移动，采集和加工使用同一个游戏时钟。进行中可取消，只有完成时才提交物品、容量和额度变化；打开整理窗口或暂停会停止计时，开始加工后窗口自动收起。

三图共用一个库存和补给架寄存账本。随身负重影响移动，打捆使用现有搬运规则；材料可以放下、回取、归架与重新领取。地面材料记录来源地图，坐标相同的另一张图不会出现副本。切换地图保留各自停留位置和来源状态，不重抽树位、不补满资源。

| 资源链 | 当前可完成的去向 | 当前边界 |
| --- | --- | --- |
| 鲜菌、林果、坚果 | 采集 → 随身运输 → 寄存 → 菌干、果干、坚果储粮 → 取回 | 尚未接主营地用餐、行商或完整季节产量 |
| 枝料、弯曲枝料 | 携带、打捆、存取；一份枝料加工为三份引火柴 | 弯曲规格保留；后续专用木作另行接入 |
| 树液 | 补给架领取一只空罐 → 装满 → 归架 → 用两份引火柴熬制 → 糖浆与空罐 | 正式季节、气候和采液窗口以后确定 |
| 长材 | 四个有限回收点中选择，共享三份额度；完成后原地落料，再搬回补给架 | 回收经营林风倒长材，不砍保护巨木；不是完整年度采伐经济 |
| 树脂、种源 | 有限容量采集、运输和寄存 | 树脂下游木作、种源定植与树位补生留待后续 |

长材尚未归架时，只阻止**来源林区**继续回收；另两图仍按自身欠料与共用剩余额度判断。搬运途中放下、换图或读档不改变归属；入架后完成该来源的交付。普通可恢复资源目前采用样区游戏时间的短周期配置，有限长材不恢复；这些时间是游玩验证参数，不能解释成正式四季与果实成熟规则。目录与配方见 [资源目录](../src/content/expedition-resources.ts)。

## 模块边界与复用

| 层 | 入口与责任 |
| --- | --- |
| 内容 | `content/forest-expedition.ts` 定义地图、树形、路线、生境、地标及资源锚点；`content/expedition-resources.ts` 定义物品、采集规格、配方与额度 |
| 空间 | `world/forest-expedition.ts` 输出 `ExpeditionLayout`；`grid.positions/indices` 是可直接绘制的三角网格，`expeditionHeightAt` 按相同三角面插值；角色、来源、植被落地与导航共用它 |
| 业务 | `domain/forest-expedition.ts` 管理来源余量、库存、来源区欠料、动作与快照；复用 `inventoryTransaction`、物品身份、目录及既有负重公式 |
| 表现 | `scene/forest-expedition-scene.ts` 绘制地形、水面、角色、来源、地标与选择；`expedition-vegetation*` 管理树形、地物、实例批次与遮挡；不自建业务时钟或发放奖励 |
| 照明 | `scene/lighting/forest-expedition-lighting.ts` 将真实冠层、地表与动画脚底适配到共用户外阴影、间接照度及接触规则；保留本模块的 renderer/资源所有者 |
| 宿主 | `app/forest-expedition-runtime.ts` 持有唯一应用状态、主循环、输入、寻路提交与样区存档写入者；`snapshot/subscribe` 向界面提供状态 |
| 界面 | `ui/ForestExpedition.tsx` 展示状态并发出选择、走近、采集、搬运和加工意图；窗口焦点复用 `useWindowFocus`，控件复用 Timber 原语 |
| 入口 | `sandbox/forest-expedition/main.tsx` 创建画布宿主、运行时和 React 根，唯一挂载/卸载 `mountTimberTheme`，退出时释放资源 |

`createExpeditionLayout(id)`、`expeditionCanStand`、`expeditionSegmentWalkable`、`findExpeditionPath` 是空间接入接口；来源通过稳定 `id`、`habitatId`、`role` 和可选 `hostTreeId` 与业务关联。未来主营地接入应消费这些模块，不复制来源状态或另建第二套地面高程。

样区存档目前使用独立 localStorage 键 `home-of-woods.forest-expedition.v1`；没有读写主营地 IndexedDB。主存档接线和跨地图进入/离开过程应在下一阶段明确。运行时允许开发检查注入 `createScene` 和独立 `storageKey`，以便无 GPU 时测试真实业务与界面；替代场景不构成 3D 渲染验证。

角色沿用已登记 KayKit 玩家与动作，菌簇/枝料沿用已登记采集 GLB；树皮、部分树形和木质 UI 继续消费仓库共用实现。新增程序植被包含十五种树/灌木形态与七种林下地物，无新增外部资产。资源所有者、来源与许可边界见 [资产登记](ASSET_REGISTER.md)；巨木根盘、横枝老枫、育苗倒木的具体后续精修见 [Blender 备忘](FOREST_BLENDER_NOTES.md)。
