# 低阶奇趣词条 VFX 词汇库（第 0 版）

2026-11-04。此稿是 **可复用的内容库与技术契约**，不是已接受的「衣」类词条池或已接线的特效服务。独立于未合并的 KayKit 换装 PR #17，先以 `main` 为基线避免把建模与效果逻辑混在一起。

## 创作定位

不是“纽扣抖两下、袖口有一片细叶子”这种只有近景放大才能看到的装饰，而是在**默认可旋转斜俯视镜头**下完整辨认的颜色、形状、环绕、短暂拖尾、环境响应。可以轻巧，不必每个词条都让 NPC 表演一段剧情。低成本 VFX 可以大量复用，但名称与意象必须经过选择，不能把任意笛卡尔积当作独立词条。

词条呈现层与 `src/content/item-vfx.ts` 中史诗/传说 **掉落物稀有度识别光效**独立：前者是装备或设施拥有的效果，后者是物品等级可见性提示。二者叠加时要限亮、限粒子，不能覆盖此前约定的柔和表面发光与关闭/简化设置。

## 两条互不混淆的等级轴：物品稀有度 ≠ 词条等级

- **装备稀有度（item.rarityId）**：普通、优秀（绿）、稀有（蓝）、史诗、传说。影响物品稀有度外观，并决定日后生成装备时的**词条槽位数与抽取规则**，但不会自动把每条词条抬成同等级。
- **词条等级（affix.grade）**：同样可采用普通、优秀、稀有、史诗、传说五档，但它属于**单个词条的效果定义**。本基础库只制作普通、优秀词条候选。高级动作和独特事件词条以后独立设计；低等级色彩/粒子词条**允许出现在高等级装备上**。
- **词条类别（affix.category）**：色彩、粒子、动作、互动事件、实用效果。**同一件装备同类别最多一条词条**，跨类别可以并存。按主要效果分类，而不是按使用的素材分类：双色粒子只占用「粒子」一类，不会因为它使用两种颜色就占用「色彩」类别；日出、雨停、采集完成是触发条件，不是类别。

例如，传说外套可以同时有「麦田余温」（色彩/普通）、「金铃落湖」（粒子/优秀）和一条将来独立设计的「外套不肯睡」（动作/高级）。这三条占用三个不同类别。再加一条「夕云莓焰」色彩词条就不合法，即使外套还有空余槽位。

装备实际拥有的词条数量另由**未来的物品生成/制作规则**决定，现阶段不定死槽位数。当前对齐的例子是绿色装备约1条、蓝色装备1–2条、传说装备可有3条；它们是策划范围，不是已执行的概率或硬性上限，其他稀有度待平衡。高等级装备的特点主要在于**能组合更多不同效果**，不必要求每一条词条都高级。

### 数据落点与生成边界

现有 `itemProperties(item).traits` 是无损扩展的词条数组，结构为 `{id,value,...}`；现有输入校验只保证**词条 ID 不重复**，不会自动禁止同类别的两个不同 ID。新增 `AffixDescriptor` 为内容定义补充 `grade` 与 `category`，新函数 `validateAffixComposition(traitIds,definitions)` 检查**同类唯一**，供将来生成词条组合、装备升级和手工挂词条时调用。

目前函数**不会自行生成词条、控制槽位数、修改存档或重写未知字段**。以后生成时先依装备稀有度决定合法条数，再在可选词条池内按物品用途/触发前置/类别互斥抽取，最后让各词条独立使用自身的等级及参数。装备外观的史诗/传说发光与具体词条表现仍是两层，不应互相覆盖或冒充。

## 库 A：精选 256 色中的 48 色

`src/content/affix-vfx-palette.ts` 使用明确的 xterm-256 编码映射，源色号采用 16–255 中可确定 RGB 的 6×6×6 立方体及灰阶区，剔除终端主题会改变的前 16 色。项目当前调色板没有规定必须使用 xterm-256；这里明确选择一个标准编码作为可复现的**编目坐标**，而不是强迫美术把所有场景材质量化到这套色表。后续若换基准调色板，应另增版本，不能暗自更改已有色号含义。

8 组，每组 6 色，共 48 色，占 256 色的 18.75%，显著低于所提出的 1/3 上限（85 色）。每色有 `paletteIndex`、`hex`、中文名字、`family`、两条意象关联。一个颜色可以形成不同词条，但**名字+意象+触发行为**应当能自洽。色号不自动决定稀有度。

## 库 B：粒子形状（6+5）

- **基础形状（普通）**：柔光圆点、小菱晶、短流线、彩纸片、空心小环、月弧碎片。由 billboard、基本线或简易环组成，偏显示型而非真实物理。
- **稍复杂形状（优秀）**：四芒星、小花瓣、小叶片、弯月、六枝雪晶。可一次建模/程序绘制后复用，不按每条词条重造模型。
- **稀有以上独立设计**：完整蝴蝶、小云朵、会变化的动植物、能离开玩家行动的衣物、改变物品或空间功能的事件等，不由本库自动升级生成。

这里的“稍复杂”是图形轮廓多一步，并不是需要新的布料求解或复杂骨骼。**复杂度与物品品级不强制一一对应**。

## 库 C：空间排布（8 套）

头顶花冠、双肩轻升、随身星环、身后扇影、脚边涟漪、两步余光、头顶一簇、身旁细落。

每套固定 **锚点 + 组织形式**，不只定义粒子名字。如「脚边涟漪」是 `at-feet + outward-rings`，不是把十个点随机撒在人物周围。当前全为**声明性参数**，可作为后续 Three.js 粒子批次的输入。

初始建议上限：单次 8–12 粒子，事件占据人物约 1.1–1.7 倍的视觉宽度，持续 0.8–3 秒；静态彩色换装可持续更久。最终通过默认缩放、昼夜和手机窄屏截图决定粒径/透明度，**不能拿近景检视器替代玩家实际视距**。粒子不得遮挡采集交互或角色脚下危险提示。

## 库 D：触发条件（14 套）

| 类别 | 预置触发 | 上游数据状态 |
| --- | --- | --- |
| 时间 | 破晓、日中、薄暮、子夜、初春首日、初冬首日 | `calendarAt(state.time)` 已提供小时/季节；特效事件适配器尚未做 |
| 环境 | 走近溪边、靠近篝火 | 场景位置/设施存在；距离进入/离开事件适配器尚未做 |
| 环境 | 雨停、入雾 | 缺少游戏可用的天气事件源，**未来功能**，不得仅凭天空材质模拟当作已实装 |
| 动作 | 迈步、停步、采集完成、制作完成 | 角色/服务有相关状态；状态边沿与一次性事件去重待做 |

**时间必须使用现有游戏沙漏**：`calendarAt(state.time)` 已消费加速后的游戏时间；未来适配器按上一个时间值与当前时间值判定区间跨越，不靠“某一帧刚好等于午夜 00:00”。12x 跳过时间窗口时仍能触发一次，但切换倍率、暂停/重载不能无限重触发。特效动画持续时间使用未加速的实时主循环时间，避免 12x 时花火闪现即灭。不要新建平行计时器。

环境、动作触发应与已有玩法事件相连，不因选择词条而编造雨雪、保暖、减速、材料加成等业务事实。触发条件只代表“何时展示”，经济效果应由单独服务实现。

## 低阶组合的审核门槛

1. **普通级词条**：单色 + 一种基础形状（或单色衣物变色）+ 一套排布 + 一个触发，适用于任何允许该类别的装备品级。
2. **优秀级词条**：仍可单色，但允许**经筛选的双色、稍复杂形状或两阶段简单呈现**；不强求每条都把资源预算用满，也不要求装备至少达到优秀品级。
3. **稀有、史诗、传说级词条**：另立创作和工程评审，不由以上四库的笛卡尔积自动生成；这些是词条自身的级别，不是装备最低品级或词条槽位数。
4. **语义关联**：例如「清溪碎波」适合溪边的水环，「霜火隔窗」适合初冬的冷暖交错；不能把“海潮蓝+雪花+做菜完毕”硬拼出一条无联系词条。
5. **使用范围**：首批挂「衣」类。未来「住」类可改物品附近锚点，「食」类可改锅/成品附近锚点，「行」类则可能改地面/背包或路径。模板共用，物品用途与行为限定仍由类别注册决定。
6. **表现分层**：换色可以重用 KayKit 的分段衣装表面，然而目前 `main` 尚不含 PR #17，旧原始合并 GLB 的衣物局部换色还需要材质区段/蒙皮适配。**候选数据存在 ≠ 已接入实际衣物渲染**。

## 待评审的例子，而非已接受词条

`LOW_TIER_AFFIX_CANDIDATES` 目前收录 13 条示例，展示普通和优秀如何从同一个库组合。包括「麦田余温」（薄暮外套单色）、「月露微光」（子夜随身小环）、「清溪碎波」（溪边脚下短涟漪）、「金铃落湖」（金蓝双色四芒星）和「丁香迎曦」（晨光双色花瓣）。它们用于检验词条命名/可读性，不进入掉落池、不分配概率、不接装备实例、不会自动生效。是否接受仍按每组 10 条的人工筛选规则进行，**修改不视为接受**。
