日期：2026-11-12。任务基线：`main` 的 `75bf51a`。本次重新授权规划并施工独立木屋内部展台；本文件在施工前单独建立，远端保留独立规划提交 `b9dfae1`。状态：**implemented，浏览器视觉验证进行中**；未合并、未发布。

## 目的与入口

做出可旋转、可近看、可操作的完整木屋内装，先在 `/sandbox/cabin-interior/` 审查。默认“初住”只有床、桌、凳、灯；“完整陈设”是用户主动选择的审计样板，另有空屋与逐件添加。正常游戏不自动得到任何家具，也不写其库存或世界存档。

本轮以朴素山林生活为范围：休息、坐读、收纳、备餐、照明、整理。沿用圆钝低多边形、暖木、奶油布与森林绿的项目风格。先做好房间和关键家具的实际观感，再实现已定义交互；不用高面数、检查数量或接口数量代替完成度。

## 尺度与空间事实

使用 Three.js Y-up，+X 向右，+Z 朝入口，地板表面 Y=0；所有模型以落脚面的中心为原点。保留主角 `CHARACTER.worldScale=1.5`，不为塞进屋缩小人物。原 GLB 及动作实测站立约 2.54 高、行走横向包络约 1.65；主线碰撞半径 0.48 不变，展台按行走最大水平半径 0.902464 采用 **0.92** 的导航包络。

房间净宽 **8.4**、净深 **7.0**、檐下 **3.35**，门洞净宽 **2.0**、净高 **2.95**。这些是本游戏世界单位，不等同现实人体比例设计。中心通道保留约 1.8 以上净宽，床侧/椅前有独立接近区。南面门向外开；入口及扫掠区禁止家具占用。北、西墙有实洞窗、厚窗台和框；墙不是贴黑色平面假装洞口。

空间注册由同一份数据生成：围护、地板/平台、门洞、房间边界、固定安装点、家具占地、支撑面、使用位、起身位、移动扫掠范围。旋转家具同步旋转其空间记录。剖切和隐藏只改变显示，不改变上述事实。

## 物品范围与行为

| 类别 | 本期物件 | 实质交互与状态 | 后续接入 |
| --- | --- | --- | --- |
| 固定围护 | 地板、厚墙、门窗、梁、双坡屋顶、门前平台 | 门扇开合；其余只观看/碰撞 | 建筑修缮阶段与原升级账本 |
| 休息 | 单人床、木凳 | 走近、休息/坐下、起身；入口点统一 | 原休息/晚间生活规则 |
| 工作/用餐 | 木桌、木碗 | 桌面支撑槽、器物独立身份；托盘式审计 | 原食物/木作/容器系统，不在展台发奖励 |
| 收纳 | 木箱、置物架 | 箱盖有枢轴与真实内腔；置物架提供支撑槽 | 原库存 location 与 mounted 关系 |
| 温暖/光 | 铁炉、提灯 | 点亮/熄灭，炉火只演示；炉脚有炉台 | 以后由燃料事务与宿主时间驱动 |
| 装饰 | 编织地毯、盆栽 | 地毯不挡路，其他物件有登记支撑 | 用同一目录增补，不用临时坐标堆物件 |

可移动家具：桌、凳、箱、床及不挡路的地毯；小道具通过登记支撑槽放到桌/架，移动宿主后子件一起变换，收回宿主时子件一并安全回到样品架。当前小道具使用固定登记槽，未开放任意桌面拖放。移动预览可旋转、取消、确认；非法位置说明原因，取消不改状态。物品的 `definitionId` 与 `instanceId` 分开；样品架取放保留同一身份，不由 scene 创建物品。

本期不实现全屋刚体投掷。门、盖是受限枢轴；家具是受规则约束的重摆，小道具是面上放置。后续可把独立 `motion`/`support` 记录接 Rapier 局部物理；几何和身份不依赖物理引擎。

## 视角与材质

- 主镜头为斜上方的舞台式三分之四视角；另有对侧、俯视、室内人眼高度、物件近景及复位。
- “随视角剖切”撤下近侧墙上部和屋顶，保留矮墙、截面与落地结构；“舞台半墙”固定打开南/东侧；“完整外壳”检查屋顶和立面。选择保留厚度完整的模块，不用透明整屋制造排序错误。
- 近侧墙附属构件随墙显示，避免悬空窗框/挂物；墙体碰撞始终存在。屋顶与墙开合不重建实例、不改变物品状态。
- 木材沿构件长轴走纹，薄弱边缘用适量倒角；布料为柔和粗糙纹理，炉体暗哑，灯仅局部发光。关闭贴图的素模模式仍能读清结构。昼/暮两套光照、平面占用/使用点覆盖、绘制量指标用于审计。
- 优先复用已安装的 Three.js skills 和实际 CC0 成品。已发现官方 KayKit Furniture Bits 1.0 的床、桌、凳、架、地毯；许可、具体文件、修整和校验值由 ASSET_REGISTER 及资源 manifest 维护。独立模型与统一调色，离线运行，不加载整屋不可分离模型。

## 架构与扩展边界

`sandbox/cabin-interior/src/` 内分 content、domain、scene、app/UI。content 注册尺寸/位置/类别/解锁来源，domain 纯函数处理空间、路线、使用及同实例重摆，scene 只消费状态并持有渲染资源，app 是唯一提交者/循环/展台保存者。

展台存储固定独立键 `home-of-woods:cabin-audit:v1`，仅记审计布置及开合状态。与主线 IndexedDB 完全分离。共享 `Resources`、木纹与原角色资源；主线源码只读引用，不另造角色比例。

对外导出 `mountCabinAudit(container, options)`，返回 `pause/resume/dispose/getSnapshot`，事件传达放置/使用意图与快照。主线接入时由宿主注入实际拥有/解锁实例、唯一保存与规则事务；展台预设不参与正式库存。先保留可用、已调用的模块边界，不铺设无人消费的服务。

每个 definition 指向 builder/model、尺寸、footprint、交互、support、motion、blueprint 来源及展示阶段；增加物件主要通过新增定义和模型完成。审计页面可逐件检视；后续物品/屋壳替换不用改相机或取放规则。

## 顺序与可见验收

1. **规划与选型**：本胶囊、固定房间方案、真实角色尺度、开放资产许可。
2. **完整视觉样板**：围护/实洞/家具/木纹/布料/昼夜/剖切/固定镜头，先看图；模型未完成不扩行为。
3. **最小使用链**：同一人物从平台进门、绕家具、到床边使用、起身、出门；不瞬移穿墙，不跳山谷镜头。
4. **陈设审计**：初住/完整/空屋，逐件添加，选择/开合/灯火，移动/旋转/非法落点/取消/收回，支持物随宿主移动。
5. **冻结验证**：针对性空间与身份测试、类型/生产构建；桌面与手机视口实际交互，固定昼夜/素模/空间图，模型网络错误及控制台错误检查。真实手机 GPU 帧率不由软件渲染推断。
