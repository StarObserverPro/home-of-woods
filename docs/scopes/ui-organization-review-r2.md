### 追加的明确视觉要求

- 不使用窗口内滚动条，也不通过隐藏滚动条掩盖溢出；按固定槽位分页，窄屏调整每页容量。
- 顶部不留大块空白：紧凑标题、分类直接接物品格，操作区贴近当前物品。
- 尽量使用已有彩色图标；物品格仅放图标、数量与选择状态，名称/用途集中到选中详情。图标控件保留可访问名称与触摸可见详情。
- 不采用细线容器边框。以经典《石器时代》的紧凑槽位、固定详情和有体积的造型边为参考。
- 用户随后明确校正材质：本项目是木头主题，外沿、标题条和角部全部采用厚木框、木纹及木作接角，不采用石质边缘。
- 参考图来自 [巴哈姆特《石器时代》新手指南](https://forum.gamer.com.tw/G2.php?bsn=1571&sn=4326)，只用于观察结构，不复制游戏 UI 图像作为交付素材。[新浪旧版视窗介绍](https://games.sina.com.cn/o/c/2010-11-03/13427570.shtml) 可核对道具、人物及固定功能窗分工。

## 观察与原因

1. 工作台的目标小窗包含 8 个顶层折叠入口。物品（整木坐墩、日用木碗）、用途（门前与火边的手作）、能力解锁（改良工作台）、图纸、改造与详情采用同一层级。小窗内展开后继续滚动，无法直接比较要做的东西。
2. 仓库首层为随身、营地、家具、图纸、穿戴，混合存放位置、物品类型和系统入口。家具页进一步按住房、扫帚、餐具、木墩等组件顺序拼装；检视状态中即使没有住房物件，也先展示其空态引导，再展示已拥有的木墩。
3. 目标详情、学习、制作、装配和改造同时消费同一个 `.target-card`。PR22 的折叠与互斥改善可见数量，但没有定义统一的配方目录和功能窗口，后续组件继续向目标卡追加。
4. 卡片重复呈现名称、普通品质、位置与完整动作句；多层边框、分隔线和半透明背景占用空间。行商从标题到第一排货物之间有余额、说明、礼包、交易模式和类别五层区域。
5. 390×844 行商实测：沙漏框 `y=63..107` 与行商窗 `y=80..762` 的标题区重叠；摇杆 `y=716..822` 与结算摘要 `y=698..761` 重叠。应统一菜单/场景输入模式及安全区，不能继续各模块单独设置定位。

根因定位：`src/ui/App.tsx` 的目标卡直接组合多个 Controls；同文件的 furniture 属性直接组合多个 Inventory；`src/ui/Warehouse.tsx` 的 TABS 固定为混合维度。涉及样式包括 `hud-layout.css`、`menu-art.css`、`merchant.css`、`clock-controls.css`。本轮不修改这些文件。

## 候选组织规则

- 常驻层：地点/时间、必要生活状态、固定的地图/背包/角色/菜单入口。镜头与帮助进入菜单；不为类比 MMO 增加本游戏没有的任务或战斗系统。
- 目标层：名称、一个相关状态、一个主动作，必要时一个次动作；走近不自动扣料。复杂操作从目标卡进入专用窗口。
- 制作窗口：制作/改造分开；按家具、工具、餐厨分类；点配方仅选择，详情集中展示外观、材料“拥有/需要”、解锁条件及一个主动作。学习、制作、装配用当前阶段替换同一动作区域。
- 物品窗口：先明确背包与营地仓库；材料/食物/家具/工具为各自的类型筛选。角色穿戴独立；已掌握图纸归制作目录，库存中的图纸实物仍是物品。远处查看与到地点存取继续遵守现有领域条件。
- 交易窗口：买/卖、紧凑商品列表、选中详情、固定结算区；赠礼作为次级入口。价格、欠款与实际结算信息保留，重复操作说明收起。
- 文案：按钮使用“取出”“存入”“学习”“制作”“摆放”，对象名由选中标题承担；材料用图标与数量表示；失败原因贴近禁用动作。长用途/来源说明在详情层，首次操作教学按需出现。
- 手机：菜单独占输入，移动摇杆收起；标题/关闭与主要动作始终可见，列表和详情分步；关闭返回原目标。没有选中项时不出现伪造操作或占位长文。

参考：[FFXIV 官方 HUD 构成](https://na.finalfantasyxiv.com/uiguide/know/know-hud/hud-name.html)、[官方游戏界面手册](https://na.finalfantasyxiv.com/game_manual/view/)。其目标栏、快捷动作、物品/角色与功能菜单分工为参考；本项目的具体布局和命名是本轮设计判断。
