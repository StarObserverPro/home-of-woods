# 粗木 UI / HUD 共用语言与接入

日期：2026-11-13。基线：main `14992fb`，独立分支 `feat/timber-ui-system`。交付在 [PR36](https://github.com/StarObserverPro/home-of-woods/pull/36)；实际合并状态与接受的验收提交以该 PR 记录为准，发布是独立步骤。

## 目标与边界

### 合并前追加：跨层网格对齐

用户已授权在本分支完成按钮、窗口与非空间消息的跨层网格对齐，补充规范后合并 PR36；PR35 保持待审。追加范围为共享布局变量、按需显示的辅助线、主游戏与活跃模块的内容边线及控件行，以及对应几何断言和截图。验收检查屏幕安全边、窗口内容边、同行控件和消息归属；分数列宽允许浏览器布局，不把所有坐标强制取整。辅助线默认关闭，不参与命中或玩法。空间跟随标签、拖动物品位置和 3D 世界规则保持各自空间坐标。

追加实现使用 4px 基本单位、8px 控件间隔与 12px 区段间隔；屏幕安全边统一为桌面 24px、紧凑 8px，并消费各边安全区。窗口内容上/侧仍为 24/20px，下方统一为 32px。移除了分类/列表的重复横向内缩、关闭按钮的负 margin 和帮助窗遗留的窄宽上限。主窗口与 `hud-notices` 使用同一个实际 CSS Grid，持久告警占独立行并为窗口留出空间；主窗口的消息则沿自己的内容边线排布。

`grid-guides.ts` 由既有主题所有者按需挂载，`?uiGrid=1` 或根 `data-ui-grid-debug="true"` 显示安全框、内容框、控件矩形与消息范围。关闭时清除绘制与监听，默认不建立辅助线绘制循环；文档级宿主会排除辅助线自身的 DOM 变更，避免调试图触发自身重绘。样板页有显式开关，Shadow DOM 使用相同实现。

本轮浏览器脚本新增实际矩形检查（同轨误差不超过 1 CSS px）、同行控件/跨行列检查、消息遮挡检查，以及同状态的干净图与辅助线图。开启与关闭辅助线须保持布局与焦点不变；原生暂停对话框须能在顶层显示辅助线。木作另检查先开辅助线、再打开 Shadow DOM 内已有原生确认窗的顺序，确认辅助线重新进入顶层且不抢走模态焦点；这是原生对话框检视，不代表业务弃料流程验收。手机追加 `gridNotice=1` 检视夹具：仅让隔离的内存存档读取失败，由真实 save-controller 产生持久告警，检查它与仓库同时出现的布局；未读取或修改用户存档。新增检查的最终结果另按本轮 PR Checks 读取，不继承先前版本的通过结论。

首轮网格实拍还发现木屋 320px 的操作堆叠遮住了人物与挪动物品。窄屏布局据此将至少 320px 高的场景与操作区分为上下两行，页面按内容滚动；短横屏保留既有场景外底部操作带。390px 仓库物品格的正方形比例与限高共同造成末列少 5.5px，已明确按钮宽度占满列轨道。持久告警夹具会按生产规则先进入暂停，检查通过真实“回到山谷”按钮继续后再打开仓库。几何对齐通过不能替代对操作对象是否可见的实拍检查。

保留森林之家的木块按钮与粗木风格，解决边缘细线、纹理拉伸、不同窗口和沙盒各用一套皮肤的问题。建立可直接消费的材质、轮廓、状态、排版和输入契约，后续模块沿用同一套机制。

本轮触及 UI 共享层、HUD 和窗口表现、独立木屋展台的界面、木作组件的主题接入接口、组件检视入口、设计约定及针对性检查。不改库存、加工、交易、物品身份、存档和 3D 场景规则。PR35 的有限锯切功能仍在其原分支，本轮不合入或重写该玩法。

## 可见验收

- 实际游戏的常驻 HUD、目标卡、仓库、路线、天气、设置、暂停与阅读使用同一套边缘及按钮状态。
- 大窗、长板、方块和窄竖构件按用途与真实尺寸生成轮廓；切角/边厚以固定像素范围控制，不随长边拉伸。
- 普通容器不用细线描边；文字区安静，粗犷感来自大切面、断续纤维、厚度和局部缺口。键盘焦点仍有清楚的宽实色标记。
- 鼠标、键盘与触控可操作；普通按钮命中区至少 44×44 CSS px，窄屏和横屏不靠缩小按钮或隐藏主操作过关。
- 木屋展台与木作 Shadow DOM 消费相同主题源；新组件检视页用于审查比例、材料、状态及布局，不维护第二份游戏规则。
- 桌面、390px 竖屏、320px 窄屏、844×390 横屏检查；冻结后取得实际截图与代表操作证据。证据图片留在临时目录或 CI artifact。

## 推进与去留

先完成一个能在实际游戏运行的视觉切片，检查轮廓和阅读，再扩到各窗口。生成器、tokens、无框架挂载器和组件检视保留为共享源；旧历史沙盒不重建，但明确归档和未来恢复时的接入要求。当前活跃沙盒纳入共享约束。

共享源码位于 `src/ui/timber/`。`surface.ts` 只生成低频多边形绘面；`mount.ts` 按尺寸和语义参数更新，统一观察与释放，缓存最多 96 项。`theme.css` 管理状态、触控尺寸和绘面回退，`game-layout.css` 管理主游戏布局，旧业务样式置于较低的 `how-layout` 层。原 R1 图标继续使用，旧木纹资源保留作历史材料，活跃界面不再依赖其拉伸边框。

`DESIGN.md` 为完整视觉与接入约定，AGENTS 只保留开发入口。`tools/ui-contract.json` 明确列出四个活跃入口与四个历史沙盒，`verify:ui` 检查共享绘面所有者、样式层、细装饰边、旧贴图与入口登记，并登记现有内联样式源。强制颜色的细边例外仅适用于其完整 media 块，不能让后面的普通样式漏检。这是针对现有约定的静态检查，不是完整 CSS 语义证明。真实布局、遮挡、文字和键盘仍需浏览器证据。

## 根据实拍修正的细节

第一轮实际浏览器回看推动了以下修改：

- 窗口正文离外缘太近，底部文字压到木框：主窗口共用 `--how-panel-padding`，正常上/侧 24px、下 32px，窄/短屏上/侧 20px、下 30px。
- 短横屏仓库有 6px 内容溢出：把搬运数量与材料分类放入同一工具行，分页继续留在物品列，不缩小命中区。
- 木屋短横屏提示、人物操作与镜头工具遮住座面和脚部：人物操作移出 canvas 区域，提示归入状态位，镜头工具改为轻量凹面并按需展开。
- 进入/退出短横屏挪动会改变 canvas 尺寸：只同步尺寸并保留手调镜头和观察点，避免工具区打开时突然复位。视角菜单内的下拉控件按 Esc 可收起菜单并返回展开按钮。
- 传统容器不能只换表皮：窗口接力时保留原打开者，暂停/阅读接管时停止普通窗口的焦点循环；拖动隐藏的控件退出 Tab 序列，改变页容量时按选中物品索引定位新页。
- 装饰参数不能依赖界面状态：物品使用稳定 ID，普通控件使用稳定语义种子；按下仅移动绘面 2px，不移动文字与命中位置。
- 刨花反馈拥有独立薄片轮廓与两端卷曲，中部保持安静，不再只是方块里的木纹符号。

完整工作流为 [Timber UI Review](../../.github/workflows/timber-ui.yml)，按 desktop、mobile、modules、baseline 四个任务并行。每份 `report.json` 记录源码版本、构建入口哈希、浏览器版本、视口、逐项操作、焦点、矩形和错误；失败先保存截图与 DOM，再恢复界面。旧版对照失败会单独记为 unavailable，不伪装成新版本失败或通过。

主游戏证据使用真实 App/runtime、正常内容与事务，只隔离存档并固定 seed `104729`、时间及检视用库存。仓库/路线/故事通过正常界面进入；阅读途中由实际“走近”动作生成路径后，沿项目既有 `__HOW_ADVANCE_SIMULATION__` 检视入口分段推进同一个固定步长所有者，避免软件渲染每帧数秒与 0.1 秒 dt 上限使行走等待失真。报告单独记录该推进，未直接改写人物位置、选择或阅读状态，不能由此推断实体设备帧率或操作耗时。

主游戏与旧版对照使用 Chromium CDP 合成视口截图，避开 Playwright 截图准备阶段的 RAF 稳定等待。Timber 工作流显式设置现有 `PLAYWRIGHT_LEGACY_SCREENSHOT=1` 开关，采用等待重绘的截图路径，并在两份报告记录该模式；[Chromium 对应特性定义](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/common/features.cc)说明了两条路径的差异。分辨率、场景和布局保持原样，截图超时不放宽。

针对软件渲染环境中反复出现的截图超时，主游戏在 `DEV + inspect` 条件下提供受控取图接口 `__HOW_CAPTURE_HOLD__`。取图瞬间通过既有唯一主循环暂挂渲染，读取浏览器已经呈现的真实画面；`finally` 按当前暂停所有者恢复循环。它不发布游戏暂停状态，捕获期间保留实际世界状态、输入与固定步长余量。报告须确认持有期间帧数和世界状态不变、焦点与窗口矩形不变，恢复后运行中的循环继续推进，原本暂停的循环继续暂停。正常操作及交互断言在释放后执行；这些截图不能用于判断实体设备帧率或真实操作耗时。

模块长页继续保留全页截图。截图失败仍写入失败报告，流程的真实关闭/清理随后执行，避免把一次截图超时误诊成后续所有菜单都不可用。木作从实际构建的 `woodworking.html` 在离线 context 打开。没有用主题样板替代主游戏，也没有通过改写产品状态绕过待检查的操作。

**最终检查结果与图片请按 [PR36 的 Checks](https://github.com/StarObserverPro/home-of-woods/pull/36/checks) 读取。** PR body 记录接受的代码提交与对应运行；Actions artifact 保存截图与结构化报告（当前保留 7 天），图片不提交仓库。GitHub 的 PR 检查可能记录合成 merge commit，因此还须结合该次 run 的 head SHA 追溯分支版本。

## 边界与后续集成

- Chromium 合成触控不等同于实体手机测试；软件渲染截图不认证移动 GPU 性能或所有系统字体表现。截图与自动边界检查各自记录，不能由零布局错误推出审美已经获用户认可。
- 检视页的“纯色回退”检验去掉纹理后的可读性；本轮没有把它当作生成器抛错路径的故障注入证据。
- 本轮不遍历木作的完整加工玩法，也不替代 PR35 的有限锯切专项验收。合流时保留 PR35 的新流程与布局，迁移本次共享主题接线和包声明路径，不能用 main 的 v0.1 组件覆盖它。
- 历史 `action-lab-r1`、`scene-r5`、`tree-variation`、`understory` 没有被翻新；恢复开发须先登记为活跃并接入共享层。
- 活动窗口的焦点由 App 的窗口状态与 `useWindowFocus` 共同拥有；绘面挂载器和视觉 `TimberPanel` 不会自动创建模态行为。

本次主题改动可通过 PR 独立比较与撤回。没有在本轮执行发布。
