# 跑动、文本选择与山谷天气

## 天气与湿度回接授权

用户接受复调效果并授权接回游戏，同时要求降水强度在完整范围内改变密度。当前施工目标为接入主体天空与光照、近景降水、水坑与覆雪，游戏时间与存档拥有天气状态，实际露天／遮雨木料随天气结算湿度并影响精细加工。正常游戏提供天气切换与强度入口，桌面和手机视口验证。采用独立稳定粒子随机数决定可见性，粒子位置与强度阈值独立。主体以本次集成后的证据为准。

已接入本地 5286 游戏入口。顶部天气菜单提供晴、阴、雨、雪、0–100% 强度与自动序列。雨雪位置保持完整范围，独立随机阈值改变密度；20% 与 80% 均覆盖全部 16 个空间分箱。真实库存、随身／地面木料与物理木料堆按位置结算，储木架有实际遮雨棚和立柱碰撞。新采获原木和枝杈初湿度为 42%，显著不同的湿料收回会分批，持续湿度变化保持拖动身份稳定。普通木作及引导装配收尾按实际配方选料湿度增加工时，沿用原整笔提交和存档。

主体构建、15 GLB／地表和 159 UI PNG 资源检查通过。天气、携带、采伐、采集、引导装配、木料和制作的 69 项专项通过，另跑包含库存交互、拖动、存档检查与密度分布的 38 项相关检查通过，两组有重复项。隔离 Edge 在实际主游戏完成低／高密度雨雪、强降雨后露天／棚下湿度差、保存刷新恢复和 390×844 天气菜单布局，页面与着色器错误为零。原始主体证据在项目外 qa-main-weather。真实手机性能仍待设备实测。

## 天气试玩画面复调

用户试玩后要求加强阴天对整体亮度的影响，修正松树尖端覆雪边界，将水坑减少为道路两侧各一两个，并略微增强水面效果。施工位置为独立沙盒的光照、覆雪和水坑材质及布局。按固定相机比较晴／阴和雨后地面，分别检查松树尖端初雪／厚雪／融雪，桌面及手机视口看图并核验着色器。复调后继续使用 4182 入口。

已实现阴云同时降低直射光、环境光、曝光与天空亮度。松树尖帽连续覆盖至上部树冠，下缘保留绿色裙边，覆雪法线复用 Three.js 已完成非均匀缩放修正的法线。水坑从 8 处减为道路左、右各 2 处，增加取天色的视角反光、明暗相间的落雨涟漪和变化的落点。当前源代码与结果均归独立沙盒。

## 跑动和阅读

现有键盘、摇杆、点地寻路共用固定步进，步速为 5.2 世界单位/秒，再乘负重系数。建议 Shift 按住跑（含点地赶路），手机用摇杆旁的走/跑切换，也作用于点地。首试倍率 1.6，保留原负重与碰撞；寻路每步位移封顶到下个路点，近身交互按原条件停步。检查现有角色包的跑步片段，步频跟随实际移动速度。用营地至林缘同一路段比空手与负重耗时，检查贴树、绕屋、抵达采集点和打开菜单后的输入复位。

游戏容器默认禁止选择文字，书名和书页正文可拖选、长按及复制。翻页控件和书外 HUD 遵循游戏默认规则，输入框保留原生编辑。按语义标记阅读正文，避免在文档根节点拦截指针。桌面拖仓库物品、手机拨摇杆和滚动书页分别实操验收。

## 天气的可见过程

| 天气 | 天空和前景 | 地面与遮蔽物 |
|---|---|---|
| 晴 | 沿用现有日照与昼夜色温 | 雨后坡地先干，洼地留水更久 |
| 阴 | 天空材质中铺一层位置高、底面平、缓慢移动的云；云盖住日盘时同步减弱直射光与阴影对比 | 保留远山轮廓和道路可读性 |
| 雨 | 比阴天稍暗；近景雨丝斜落，镜头边缘偶尔挂一滴，拉长滑走 | 泥路斑块从内向外洇深，低洼处渐渐连成浅水坑；坑面取天色，间歇出现落雨细圈 |
| 雪 | 大小两档雪片随风错落，小片交代纵深，大软片缓慢掠过近景 | 屋脊与缓坡屋面先露白，帐篷顶缝形成窄雪带，树冠逐层托雪；檐底、帐篷侧壁和树干保留原色 |

扩展现有天空参数，把天气对直射光的影响叠到昼夜计算之后。地表沿用地形采样，在预选洼地验证坡度、高差与遮蔽，用固定种子生成稳定湿斑。雨丝用相机附近的一批线段，镜头雨滴用少量透明贴片模拟亮边和暗底；雪用同一粒子池思路，批量点精灵随深度缩放。雪帽先在上表面按朝向、部件和高度混色，在近景屋脊、帐顶和树冠上沿用简化几何补轮廓。按屋顶覆盖裁去室内降水，进屋后停止新增镜头雨滴。切晴后雨丝先停、水滴滑落、积水渐退；积雪融化后给地面和露天木料留下湿意。

参考 [Three.js 点精灵雪花源码](https://github.com/mrdoob/three.js/blob/dev/examples/webgl_points_sprites.html)的批量绘制，以及 [Codrops 镜头雨滴](https://github.com/codrops/RainEffect)的滴形和滑痕。首试用项目自产小贴图与程序几何，避免整屏折射、逐滴碰撞和实时反射。若引入具体文件，先登记对应版本、文件许可与署名。

## 天气、木料与工作

天气按世界种子和游戏时间生成有持续时段的序列；时间推进、睡觉和读档消费同一序列。降水强度、地表湿润、积水和积雪分别有过渡时间。画面消费状态快照；规则按游戏时间段结算，粒子数量和帧率不参与计算。

首试给木料批次记录干爽、微潮、湿透三个显示档，内部保留连续湿度与上次结算时刻。露天木堆淋雨渐湿，棚下停止直接淋雨并慢慢风干，室内干料保持稳定；落雪先覆在表面，融雪再逐渐洇入。刚砍木材的初始湿度单独配置。转移前先结算原位置，拆堆继承湿度，明显不同湿度的批次分开，避免收放一次就洗掉湿度。

先接两道能直接比较的操作：粗锯、劈柴允许使用湿料，精细拼装使用偏湿料时增加收尾工时，选料时预告；若对应工序当前没有时间维度，沙盒先用一次可计时的收尾动作验证。玩家可以换一批干料、提前收进棚下，或照常用湿料完成工作。首轮不设随机报废。验收时把同一批木料分成两份，分别露天和遮雨，经历同一场雨后加工同一件作品；比较湿度、提示和实际工时，再检查拆堆、存取、跳时与重启。

## 施工与验收顺序

1. 单独验证跑动和书页选字。天气先建项目外的独立沙盒，入口落在一个能同时看见泥路、木屋、帐篷、树冠与木堆的小营地，提供四种天气及过渡预览。
2. 固定相机看阴云遮日、初雨、积水、初雪和融雪，再沿营地跑一圈、旋转镜头并走入遮蔽处。桌面与手机同视角分别比较晴天和雨雪的帧耗时分布、绘制调用与粒子覆盖面积。首轮性能目标为手机天气额外帧耗时不超过 3 毫秒，以实测确定粒子上限；优先减屏幕覆盖与水纹密度，保留雪帽和地表湿痕。
3. 沙盒接入露天、棚下两堆木料和同一道工序，验证完整天气过程、工作差异及重载连续性。试玩后决定继续隔离调整或接回主线；获准后按现有 content、domain、scene、app 分工接入，保留复用的配置和验证流程。
