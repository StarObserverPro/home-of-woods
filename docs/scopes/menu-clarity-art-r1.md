# 菜单交互与图标接入 R1

2026-11-05。用户明确要求深入优化各菜单和仓库，并使用已审阅的 UI 美术批次，授权回接对应素材。

- 目标：卡片选取、当前选中、物品所在位置、可执行动作与执行结果一眼可辨；仓库、随身、行商、图纸、家具和穿戴采用一致图标与交互语言。
- 涉及层：`src/ui/`、必要的 UI 纯辅助模块、采用的 `public/assets/ui-r1/`，资产登记与交互文档。沿用唯一库存、领域命令与存档。
- 可见验收：点卡片只选中；存取／穿脱／买卖／制作／摆放经显式按钮发意图；仓库支持名称检索、分类、有库存默认视图和手机详情返回；交易前可核对待结算清单；桌面、手机横竖屏可读可操作，保留 44px 触控与 Esc。
- 不涉及：把未获准的营地生活沙盒整体接回、增加新物品玩法、改数值／掉落／存档协议、部署、PR 或合并。
- 资产：仅采用当前菜单真实使用到的生成图标／皮肤；细分和五级素材不能虚构尚未实现对象，缺图使用明确通用符号，不给未知物品套上已知物品外观。
- 基线：本地 main `e2e04a5`；已有 `sandbox/camp-life/` 和其 scope 属其他工作，本轮保持不动。
- 施工期间，另一项已获明确授权的工作把营地生活接入本地主体（见 `camp-life-mainline-integration.md`）。本轮逐段保留其新增实现，并适配相关界面；不把那些领域、模型和生活交互改动计为本轮交付。
- 回退：撤回本轮 UI 文件、采用图标目录及相应文档即可；无领域和存档迁移。

## 已实现

- `GameIcon` 与语义映射共用已审阅的 79 个图标；64／128px 版本和 1 张空白物品格进入生产资产，共 159 PNG，约 2.35 MiB。已知但缺少专图的物资使用通用物品图，未识别对象显示问号。
- 仓库默认仅显示有库存，按类别排列；名称／品质检索、类别过滤、显示未持有、当前选中勾标、库存数量、具体存取地点和“营地 → 随身／场景”动作均可见。长说明折叠，取出／摆放优先出现。
- 手机使用列表 → 详情 → 返回的路径；短横屏使用左侧分类栏，把物品滚动区域从首版约 50px 增到约 179px。所有检查到的仓库按钮均达到 44px。
- 穿戴先选槽位，再明确穿脱；八件基础衣物的身份保留。图纸默认可使用，永久／次数／未获得有独立标签，目标物图标配图纸角标。
- 家具图片不再伪装成点了就摆放的选择卡；使用明确的摆放按钮，并保留按钮拖入场景的路径。门铃、扫帚、餐具和工坊入口沿用同一图标语言。
- 行商买卖统一先选详情，独立加减／待售按钮准备清单，显示结算件数、余额、还旧粮款及赊账。修正了旧预览未先扣除旧粮款的计算差异；真正结算仍用原领域事务。
- 工作台的木墩、门前手作、装配、炊具、木碗与扫帚按具名折叠组呈现，同一时刻只展开一组；展开本身不学习、不制作、不扣料。进行中的装配自动展开原任务。
- 物品工具按钮可再次收起；打开镜头先关闭物品面板，避免按钮有反应但浮层被盖住。

## 实际验证

- TypeScript 与生产构建通过；`verify:assets` 验证原 15 个 GLB 和地表，并新增 159 个 UI PNG 的路径、哈希、PNG 头与尺寸检查。
- `merchant-order-preview`、`merchant`、`carrying`、`wardrobe` 共 35 项通过。新增的 3 项预览测试对照实际交易领域提交，覆盖旧债、粮袋赊账、同类收购限制与失效实例。
- 实际 `App` + runtime + domain 的临时内存检视：取出 1 份精品枝杈，营地 3 → 2、随身 0 → 1；存回后营地恢复 3、随身归零，总数不变。选帽子时仍有 8 件衣物且帽子保持穿戴；明确脱下、穿回后数量与身份不变。
- 行商实操：仅点选帆布时余额仍 500、清单仍空；加入 1 件后预览 410，确认后余额 410、帆布 2 → 3、产生 1 张回执；一件普通坐墩显式加入待售并确认后余额 535、坐墩 4 → 3、回执累计 2 张。
- 名称检索“原木”返回正确单项；图纸默认 6 张可用；工坊切换两个类别时分别只有 1 组展开，任务保持 null。家具没有无文字的图片动作按钮，摆放有明确按钮。Esc 收起后仓库节点数量为 0，可再次打开。
- 桌面、390 × 844、320 × 640 和 844 × 390 浏览器视口检查。已加载图片无失败；已检查视图无横向溢出，仓库与行商按钮均有 44px 触控区域。最终工坊画面 shaderErrors=0、contextLost=false，浏览器错误日志为空。
- React 检查：列表使用物品／实例／图纸稳定 ID；选择不改变领域数据；图标配文字、压下态、焦点轮廓；材料普通滚动与拖拽按钮分离；没有新请求串行链、新状态账本或场景循环。

## 检视入口与边界

本地验收时曾使用临时 `tools/fixtures/menu-art-review.html?inspect=1`：它运行真实 App 和运行时，把初始检视状态与保存适配器全部留在内存；关闭或刷新即重置，`scene=merchant`／`scene=workbench` 分别检视行商和工作台。该路径只记录当时的验证方法，fixture 不随本合批交付，也不是生产或构建入口；当前游戏运行方式见根 README。

最初会创建独立本机检视存档的入口被自动审批拒绝，未执行写入；已替换为内存适配器，不读写现有 IndexedDB 世界存档。正常游戏仍沿用原存档路径。UI 检视过程中未测试真实手机设备，也未将相邻营地生活模块的完整场景验收归为本轮完成。

以上结果属于菜单 R1 的本地验收截面，当时尚无该轮 PR、远端合并或部署。其已接受的源码、正式图标和文档随营地生活合批交付；CI 与远端合并状态见[推进记录](../CAMP_LIFE_PROGRESS.md#规划来源与交付状态)及所属 GitHub PR / main。并行营地回接代码与来源文档保持其独立责任。
