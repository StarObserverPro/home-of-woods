# 三片林地：程序资产与 Blender 精修接口

本轮已经提供可运行的程序模型。这里记录后续精修位置与替换合同，不把下列建议列成当前模型缺失，也不要求另装 Blender 才能游玩。

## 已有表现与所有者

`src/scene/expedition-vegetation.ts` 管理共享树形、几何、材质、逐实例树冠遮挡和统一释放。地块尺寸和实例身份来自 `content/forest-expedition.ts` / `world/forest-expedition.ts`；模型不生成经济、不创建时钟，也不经过 `actions/tree` 的普通采伐断面修整。

已接入的造型家族为红杉式高干巨木、柔垂铁杉、云杉、冷杉、老松、侧柏式针叶树、栎、枫、山毛榉、桦、杨、榆、白蜡，以及多干榛丛和果丛。松、云杉、冷杉、栎、桦、杨、榆复用现有 `forest-shapes.js` 的冠形与枝级；其余使用同一块面、渐细枝干与色板语言补齐。`bark-surface.ts` 的两张共享树皮纹理继续用于近中景木质部分。

设计采用明确的枝干层级、固定变体和少量不透明冠团。没有逐片树叶、透明叶卡、密集绒毛或镜面湿皮。近中景保持相同冠团与骨架，远景减少截面和冠团面数，物种、实例 ID 和尺寸不随画质切换。

程序植被技能中的结构化分枝方法只用于有界枝级与确定性排布。这里有意采用本项目的低多边形冠团、哑光标准材质与距离重复的树皮 UV，不宣称复现写实 Ash Medium 的叶卡数量、几何数量或风动。

## 尺寸与部件合同

世界约 2 单位对应现有角色全高。树木的 `height` 是落地点到树冠最高点的高度，`trunkRadius` 是主干规格，`crownRadius` 是冠层水平包络半径；布局给出的规格是模型输入，不能在美术导出后再额外缩小角色。

| 对象 | 原点、轴向与尺寸 | 必须保留的分件 |
| --- | --- | --- |
| 站立树木 | 原点在主干落地点；+Y 向上；局部 +Z 为记录朝向；游戏应用 `height/10` 的等比实例缩放 | `trunk`、`roots`、`crown`、可选 `moss` |
| 枯倒木与育苗倒木 | 原点在木段平面中心；长轴 +X；下缘略埋入地面；长度和半径由 feature 参数确定 | 木质侧面、端面、覆苔、幼树分别可辨 |
| 翻起根盘 | 根盘主要位于 YZ 平面，断干向 -X；原点位于根盘下方地面 | 土根盘、主根、断干、覆苔 |
| 横枝苔帘 | 枝条沿 +X；`height` 是承托枝高度；苔帘从枝表面向下连接 | 承托枝、苔帘；不得仅导出悬空绿条 |
| 蕨与灌丛 | 原点在地面根部；+Y 向上，不能靠整体漂浮避免地面穿插 | 根部/枝条与绿色体块 |

单树组保持干冠分离。实际林地向工厂传入唯一地表 `heightAt`：根盘和根部苔块消费这个地表函数，在建图时贴合后分别合成整图批次，树干与冠层继续实例绘制。遮挡只改变冠层逐实例可见权重，干根保持不透明。模型替换不能把整棵树并为一个不可分离网格。

程序根肋在离主干约 1.18 倍干半径处仍有体量，远端逐步埋入地面。布局碰撞应覆盖约 1.55 倍干半径；最外侧低薄根允许跨过。任何替代模型都要重新核对这条边界，不能只改可见根盘而沿用更窄碰撞。

## 值得精修的三个重点

### 巨木根盘

当前版本已有 5–7 条相连、渐细、末端入土的根肋，巨木基部带低矮苔块。红杉式地标的主干与根部不需要等待外部模型。

后续 Blender 精修可以增加两三处宽而有差异的根沟、树干基部向根肋的连续过渡，以及局部包裹石块的根形。优先修地面至约一个角色高的近景区域；不以全干增加细面数代替根部形态。

固定检查实例：`expedition.upper-elder`，布局树高 48 单位。替代资产先以 10 单位树高导出，保持主干和冠层包络规格，近景根部必须与原碰撞匹配。若根沟扩大到可站人的空间，应明确提供新碰撞代理，不能只扩大视觉网格。

### 横枝老枫

当前版本已有高处主冠、较低的弯肘横枝以及真实连接在横枝上的多束苔帘，普通枫树不带同样的地标横枝。

固定检查实例：`expedition.mixed-old-maple`，布局树高 25 单位。精修重点是主干分叉到横枝弯肘的连贯体积、枝条上面附生苔块和向下分束的苔帘；不增加密集藤蔓、根须或透明卡片。按当前程序尺寸，特殊横枝从归一高度 2.6 延伸至约 4.1，水平最远约 0.94 倍冠半径，之后统一按实例比例缩放。

替换时苔帘上端必须落在承托枝表面。横枝伸入的空间要避开主路、角色站位与菌点交互位置；不能只在俯视截图里藏住穿插。

### 育苗倒木与菌木

当前版本已有不完全笔直的倒木、断枝、简化端面年轮、覆苔，以及沿木面伸到地面的幼苗根；普通倒木和育苗倒木分别可用。菌落本体由资源表现模块按 source 锚点挂接，不由木模型生成奖励。

后续可精修一侧腐朽缺口、断端纤维以及根盘脱离土壤的轮廓。默认倒木长 8、半径 0.65 单位；育苗倒木的幼树高度另由 `height` 指定。替代时保留菌落的外露侧面和角色靠近侧，不能将采集点封进实心木壳。倒木侧面朝向与资源挂点需一并检查。

## 材质、面数与许可

共享材质为木质、远景木质、冠层、冠层深度、苔藓和通用林下六类；不是逐树新建材质。普通树主要依赖顶点色、少量树皮纹理和真实块面，不依赖独立贴图组。原型将每种树的三档稳定变体缓存，空间批次只维护实例矩阵及冠层遮挡权重。

程序源码与复用部分来自本仓库，没有新增外部模型文件；不能将本轮生成资产笼统标成 CC0。未来从开放模型修改时，仍须核实具体文件允许修改、游戏使用和在公开仓库再分发，记录来源、许可证原文和改动，不用“免费下载”代替许可。

## 检查与替换顺序

先在实际林地、现有角色与游戏镜头下看轮廓、根部接触和路线，再检查孤立模型。近、中、远应保持同一棵树的主体身份；形态精修不能改资源池、采伐资格、刷新或运输限制。

几何检查已覆盖三张布局的数值有限性、地标实际高度、根尖与同一地表的接触，以及重复批次创建/释放后缓存计数。材质检查使用已安装 Three.js 的标准及深度 ShaderLib 展开插入的 shader chunks，核对属性与逐实例数量；这不等于 GPU 编译通过。浏览器画面、遮挡与实际行走仍需要可用 WebGL 环境下的场景组合验收，本备忘不将未执行的实机检查标为完成。
