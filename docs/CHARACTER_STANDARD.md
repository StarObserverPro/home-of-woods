# 人物美术与接入规范 · HOW-CHARACTER-1

适用于林工、常来行商、邻居及偶尔来访的人物。依据 2026-11-24 的选型决定。**本文件规定制作目标；它不表示六位新角色的模型已经到位或完成改装。** 本轮实际实现和验证见 [scope](scopes/character-unification.md)。

数值唯一来源是 [`character-quality.ts`](../src/content/character-quality.ts)，待机参数在 [`character-motion.ts`](../src/content/character-motion.ts)，选型与换装配色方案在 [`character-roster.ts`](../src/content/character-roster.ts)。原有世界、装备和 NPC 身份仍由各自模块管理。

## 1. 分档：控制可见精细程度

以下都指 **LOD0 单个人物完整穿戴时实际提交的三角形**，包括身体、头发、衣服、常驻背包和附件；不是 Blender 四边面数，也不是压缩文件大小。临时拿起的游戏道具另记，不能把常驻货包移入“道具”来绕过人物预算。

| 档位 | 制作目标 / 硬上限 | 身体、头发及服装目标 | 常驻附件目标 | 材质 / 单视图 draw 上限 | 主颜色图 |
| --- | ---: | ---: | ---: | ---: | --- |
| 主角 `hero` | 12,000 / 16,000 | 9,000 | 3,000 | 4 / 4 | 1024²，近景可用 2048² |
| 高频行商 `trader` | 9,000 / 12,000 | 6,500 | 2,500 | 4 / 4 | 1024² |
| 高频邻居 `neighbor` | 7,500 / 10,000 | 6,000 | 1,500 | 3 / 3 | 1024² |
| 普通来客 `visitor` | 6,000 / 8,000 | 5,000 | 1,000 | 3 / 3 | 1024² |

身体和附件可以在**同一总额内**交换预算；目标用于决定精修重点，硬上限用于控制接入成本。三角形多于目标但在上限内，需能指出改善的轮廓、面部或关节；少于目标而画面已经一致，就保留。不能通过无效细分把每个人“补到同一个数字”。

主角保持最高制作优先级。常来行商比邻居略高；传奇商人 E 暂按低频来客档，靠宽外套、色彩和成组工具表现身份，不因“传奇”多加面数。如果以后改变出场频率或特写需求，先调整其档位及合同记录。

目前公开 `player.glb` 和 `visitor.glb` 分别实测 7,574 三角形、6,735 导出顶点、23 骨、一个材质/primitive、1024×1280 颜色图。它们是保留的 **legacy 回退**，不能冒充新图集标准通过。J01 与四位 NP120 文件在用户本地；未取得时面数、贴图成本和最终分档符合度保持未测。

### 不同来源统一到什么程度

先看林工在同一相机下的头宽、头身比、手脚厚度和脸部简化程度；常规成人约 4–5 头身只作初筛，不把矮胖铁匠、长者或年轻来客拉成同高同瘦。头和躯干的比例、靴子体量、肩线、眼睛可读性比三角面数接近更重要。

修整顺序：统一轴向与脚底 → 轮廓和头身比 → 面部与关节变形 → 衣服大块形状 → 材质/配色 → 小饰物。高精模型优先去掉内层看不见的衣片、饰件背面和密集平面细分；保留脸、手、肘膝弯曲圈、帽檐、外套边缘。低精模型只在真实缺少弧度或变形支撑的地方补线，再转移权重、修 UV 和法线。

## 2. 十九世纪末林地穿搭

方向是荒野西部的耐用工装、Victorian 时代的背心/衬衣/围裙轮廓，以及少量蒸汽机械附件。使用帆布、厚棉布、皮革和旧黄铜；不套用现代城市制服，也不做满身小齿轮的机械盔甲。

| 表现 | 制作方式 |
| --- | --- |
| 贴身衣袋、缝线、补丁、扣眼、小铆钉、平贴绑带 | 颜色图为主，必要时烘轻微 normal/粗糙度变化；不逐个加独立网格 |
| 鼓出的腰袋、货包、工具卷、帽檐、外套下摆 | 影响剪影，保留少量干净几何；不能只画一个阴影假装有体积 |
| 手杖、手持工具 | 独立真实挂点，计入携物姿态约束；不能允许触头小动作把工具挥进脸里 |
| 挂表、徽记、少数黄铜扣件 | 保留一到两组清楚的亮色焦点，远景不产生密集闪点 |

**F 的具体改装**：保留已接受的粉色侧辫、奶油卷袖衬衣、苔绿背心和野外短靴；补两个鼓出的腰袋与一个斜挎货包，另画四至六处胸前/裤侧贴袋。让轮廓能看出带货，同时区别于林工的蓝工作服与小背包。原改装图是设计参考，不是已经生成的网格或 UV 图。

### 颜色与材质

| 用途 | 统一颜色 |
| --- | --- |
| 暖帆布 | `#d8c9ab` |
| 苔绿 | `#69745a` |
| 皮革棕 | `#735443` |
| 靛灰蓝 | `#586979` |
| 锈红 | `#a9654d` |
| 旧黄铜 | `#a28b5a` |

大致按主色 70%、辅色 25%、强调色 5% 安排服装面积，不逐像素强制配额。肤色与毛发独立保留人物差别；换衣颜色不能全模型乘一个色值，连皮肤和眼白一起染。F 以苔绿/帆布/棕为主，E 保留灰蓝外套与绿发，G 用赭棕，J 用围裙暖白和靛蓝/锈红，K 用低饱和绿，L 用皮革棕与炭灰。

基础 roughness 参考布料 0.88、皮革 0.72、金属 0.48，作为作者起点而非全人物统一常数。布/皮 metalness=0，金属通过局部遮罩表达。沿用项目光照和阴影，不在人物贴图里烘固定方向的强高光或大块硬阴影。

## 3. 贴图、变体与骨架

NPC 主颜色图统一 1024²，主角按近景需求允许 2048²。可选 normal ≤1024²，ORM（遮蔽/粗糙度/金属）≤512²，独立眼睛图集 ≤256²；未用通道不为了凑规格添加。颜色图按 sRGB，normal/ORM 按线性数据读取，保留 mip。全角色唯一解码图片预算：主角 6×1024² 像素、其余 3×1024² 像素；压缩文件小不等于显存小。

以一致世界尺度量 UV 密度：身体约 512 texel/m，脸约 768 texel/m，优先保持同批 ±20% 的接近程度。这是制作检查，不由审计脚本假装从模型包围盒得出。脸、手、货包正面优先分配清楚的 UV；微小饰件不要各占一张 1K 图。

每个可复用来客准备 **三套总外观**：苔绿帆布、靛蓝工装、锈红旅行装。共享同一网格、骨架、UV 和动作；变体换主颜色、衣袋形状、补丁和徽记，normal/ORM 可以共享。`CHARACTER_TEXTURE_RECIPES` 当前是已登记的绘制方案，**尚无六位新人物的实际贴图文件**。完成后在 intake 的 `variants` 填真实 `baseColorFile`，工具检查实际尺寸。

换皮肤可以为另一名来客提供外观，但必须单独分配稳定 `npcId`；已有角色换衣只换 `lookId + variantId`，不能重置记忆、来访日历、商货或交易次数。面部图集及眨眼材质不被衣服变体覆盖；材质变体由模型/Resources 缓存所有者释放，不原地改共享材质。

导出为嵌入图片的 GLB，+Y 向上、+Z 为适配器的前方，脚底接世界地表；源骨架朝向通过模型局部适配处理，不在现有绑定上随意 Apply Transform。每顶点最多 4 个有效骨权重、每人物最多 64 骨、最多 8 个 morph 通道。原 NP120 的 50 骨保持名称、绑定和动作时序；不为轻微晃动另造一套骨架。

新增角色需有躯干/胸/头、左右上臂/前臂/手和腿足的明确映射，以及可重定向的站立/行走动作。OBJ 只有网格时必须补绑定；网页写“OBJ”不代表已经有骨架或动画。短裙、外套和背带要检查迈步、抬手与拿货时穿插，不能只验 T-pose。

眼睛优先复用真实 blink morph、原眼皮/眼球骨或已制作的开闭眼图集。现有 J01 接原 blink 图集；通用层识别 blink/look morph 和眼骨。没有眼部通道时先报告能力缺失，保留轻微头部视线，不在烘死的脸上自动贴一对假眼睛。狐狸的眼睛 UV 坐标不可直接套到人脸。

## 4. 待机表现与动作优先级

共用层只在既有主循环内叠加上半身局部旋转：约 4.2–5.4 秒一个轻微呼吸周期、8.4–11.2 秒的慢摆、停留后再变化的视线和按角色 ID 错开的眨眼。根、骨盆、腿足位置不随待机漂动。连续空闲后，稀疏窗口可出现约三秒的理领口或手触头侧，不能所有人同步循环。

顺序固定为**撤销上次附加姿态 → 原动作/IK/持物姿态 → 本次轻微附加姿态 → 脚底/渲染更新**。行走、采集、砍树、祈祷、搬运、坐读和正在占用手部的动作具有优先权；需要持杖或拿货的未来角色也必须传入 `handsFree=false`。对话不插入自顾自摸头的手势。暂停与读档重建不补演错过的小动作；减少动态效果归零附加晃动、视线、眨眼及手势。没有另一个 RAF、计时器或动画发奖回调。

现有公共回退没有可用眼部形变，诊断将如实显示 `eyeSupport` 为 `none`；不能把头部微动宣称为眼球动画。现有阿榆沿用其身份和穿搭，仅接共用表现。距离 LOD 的新增模型和贴图切换仍须在具体模型到位后验收，本轮不声称已制作各角色 LOD。

## 6. 同一条接入流程

1. 在 [`intake.json`](../tools/characters/intake.json) 登记来源、文件、档位和 `pending`。先实际检查三角形、图集、材质、权重、动作与面部能力，不采用下载页合集的“5K/30K”标签作测量。
2. 对照 J01 的同镜头正/侧/背面修比例、衣服和轮廓，再做必要的重拓扑或减面。修改副本，不覆盖源件。
3. 重排/复用 UV，按第 2–3 节改色、画衣袋和烘焙细节；出三套纹理。实际有轮廓的袋子补少量网格。仅换颜色不能完成服装体积和绑定修整。
4. 检查脸手、走路、抬手、持物和脚底，接现有语义适配器；跑检查，再看主游戏同镜头与手机视口。通过的制作审查逐项设为 approved，最后改为 ready。文件可解析不等于已接入游戏。
5. 有公开分发依据的最终文件再登记 ASSET_REGISTER 与运行时 manifest；本地文件继续走本地资源路径。正式接入不从素材网站或临时下载链接热加载。

```bash
# 实测一个文件，生成可对照的报告。
node --experimental-strip-types tools/characters/audit.mjs inspect path/to/character.glb --json .cache/character-audit/before.json

# 当前清单；缺失与待制作明确列出，不假报完成。
npm run verify:characters

# 某一批已准备好交接时，禁止遗漏 pending 项。
node --experimental-strip-types tools/characters/audit.mjs validate --config path/to/batch.json --strict --require-all

# 离线简化先 dry-run 查看网格名；去掉 --apply 即只报告。
blender --background --factory-startup --python-exit-code 1 --python tools/characters/normalize.py -- \
  --input path/to/source.glb --output .cache/character-intake/review.glb \
  --tier visitor --mesh Body --apply --report .cache/character-intake/reduction.json
```

`normalize.py` 从同一份 TypeScript 合同读取目标。只处理显式选中的 mesh；保留 morph 网格、脸手骨权重区域、明显关节混合区、UV 边界及 `HOW_Preserve` 顶点，保护区的坐标/UV/权重一旦发生变化就恢复该 mesh。达不到目标便报告需要手工重拓扑，不强行减烂，也不把低面模型细分到目标。它不重画纹理、不自动绑定 OBJ、不自动判断剪影质量；输出仍要再次审计和看图。Blender 的 [Decimate 工具](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/mesh/cleanup.html#decimate-geometry) 与 [glTF 导入导出](https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html) 是所用离线步骤的接口依据。

审计区分 `pending` 待制作、`legacy` 旧路径、`ready` 新接入。严格检查拦下 ready 的真实错误和 legacy 的文件损坏；pending 仍完整报告问题，不能算通过。`--require-all` 用于明确的一批最终交接，阻止遗漏未完成的素材。比例、剪影、面部表现及穿插由实际画面审查，工具不会伪造“自动统一画风”。

## 7. 后续更新规则

改变档位、面数、图集或骨架要求时，在同一个 PR 更新 `CHARACTER_QUALITY_VERSION`、数值源、本文表格、intake 的 contractVersion 与相关测量/测试；不得只在聊天里决定一个新值。只修改角色配色或服装方案时，更新 roster 与对应资产记录；若预算不变，不必增加技术合同版本。

每次模型 revision 保留源文件标识、处理说明、前后审计和实际视觉状态。旧记录只能证明旧文件，不自动给新改装通过。J01 本地模型、六位新候选和三套贴图未到位的部分都要继续列在本轮 scope，直到真实处理和验收完成。
