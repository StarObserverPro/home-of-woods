## 一、想交付的体验

玩家从帐篷、残破木屋和粗工作台出发，通过采集、制图纸、加工、摆放、修缮及学习新工艺，把营地逐渐建成有生活气息的家。物件必须先具有合理的普通用途；更稀有的词条让它产生有趣而可信的特殊行为。默认斜俯视镜头下，玩家能看见自己制作、安装、移动、使用物件以及营地的变化；不把游戏做成由文字和菜单驱动的网站。

玩家手艺有限：基础手作能做木墩、木牌、简单木箱，精密框架、转轴、阀门和自动机关需要相应设施、材料和图纸；但**工艺复杂度、物品稀有度、单条词条等级**相互区分。歪歪扭扭的普通木箱也可能拥有罕见的神奇词条；精密机械可以是普通级。特殊能力不能凭空免除基础结构、真实原料和应用场景的前置条件。

这三个阶段**不是游戏自然日、人物等级或 PR 个数**；以体验闭环和共享能力的完成为过渡标准。每阶段 agent 自行选择合理的技术方案及工作切片，不必按本文件分支名或例子逐字施工。

## 二、当前库具备什么、还缺什么

已经进入 main 的可用基础：

- 图纸与粗木工作台的制作／库存闭环；独立 Item 实例、品质、稀有度、可扩展词条、持久化、摆放与回收。
- 参数化制作的数据契约：首批 solid 与 supported-surface；预设木墩已接线，复杂装配 UI、更多几何原型和多工序操作尚不是完整可玩能力。完成品是**一个 Item 实例**，装配散件不作为永续库存。
- 可制作物与固定设施分开：独立道具的 inventory / world / mounted 互斥归属、宿主槽位及装卸规则已有基础；门铃、纸条箱、铜壶等仍是 planned 样例，不等于已经有可用的图纸、模型、安装操作或效果。
- 本体基础动作／词条动作／局部运动分别登记的契约；大部分仍为 planned，不能以“注册完成”冒充可用效果。
- 木屋、帐篷、火塘的固定外部改造和基础修缮，仓库拖拽与搬运；行商铜币、基础食物和晚间节律；已整理的 HUD 查看—走近—操作路径。
- 低阶颜色、粒形、排布与触发候选库，以及已有物品稀有度视觉表现。**候选库不是已经能在住类物件上运行的特效播放器。**

当前重要空白：还没有完整的澡堂／浴室和相关洗浴流程；天气、风、湿度及材质干燥、真实燃料与热量、仓储容量、宠物长期归属、复杂双角色生活互动等不能当作现成基础。有基础汤锅、座位或动物偶遇，不代表上述全部系统已经成熟。对这些缺口应按实际需求逐项补最小受量和事件，不预建庞大生活模拟器。

已有分工和合同以 [参数化制作](PARAMETRIC_CRAFTING.md)、[独立道具去向](ITEM_DESTINATIONS.md)、[道具行为](ITEM_BEHAVIORS.md)、[设施外部模块](CAMP_EXTERIORS.md)、[词条视觉基础库](AFFIX_VFX_FOUNDATION.md)、[HUD交互](HUD_INTERACTION.md) 为准。本文不替代这些契约，也不要求重构已有系统。

## 三、先重新判断对象身份，再开放词条

| 归属 | 判断方式 | 典型对象／词条 | 规划边界 |
| --- | --- | --- | --- |
| 独立 Item | 能独立制作、持有、摆放、安装、拆卸或换位，效果归物品自己 | Z91 松果门铃、Z58 门前纸条箱、Z73 铜壶、Z60 守夜木偶、Z81 木箱大胃王 | 宿主只提供安装点、环境和事件；拆下仍是原实例，不把词条复制进木屋或火塘 |
| 固定结构／设施升级 | 本质是对建筑形体、承重、加工或容量的永久改造 | Z05 旧木留纹、Z07 雪避门阶、Z31 容量、Z38 晒木设施、现有修屋顶／火塘支架 | 延续固定升级账本；不能把早期固定外装无偿复制为可携带 Item |
| 正常用途与附加词条 | 物件普通功能应独立成立，稀有属性才是特殊表现 | 普通门铃会响，特殊门铃另有变奏；普通铜壶能用，特殊壶再报沸 | 不应抽不到词条就不能正常使用该物品 |
| 环境／系统作用 | 没有自然可独立持有的“物件” | Z42 脚印、Z50 树影、区域天气与季节反应 | 不强行物品化；保留正常场景规则 |
| 修改候选 | 用户仅提出修改方向，尚未正式接受 | Z52 星座难度、Z67 泡泡渲染性价比、Z92 不靠谱预报等 | 先按修改意见确认形式／成本，再决定是否纳入具体阶段 |

制作解锁与词条稀有度不强行捆绑：普通结构受设施、材料、图纸限制；词条附加能力由实例、相容性、触发条件和内容审查决定。高阶行为可能来自神谕或高级图纸，但不把“传说”直接等同于复杂机械精度；一件物品可以拥有多个**不同类别**的词条，物品稀有度与单条词条档次仍分开。

## 四、三阶段路线

### 阶段一：让普通道具真实活在营地里

**目标**：从“数据库中有独立物品和 planned 安装槽”推进到玩家可以真正**获得图纸—制作普通物件—入库—摆放／安装—使用—拆回**。不重做数据模型。选择少量高辨识、低前置、各有不同归属的可见样板，打通对象和玩家的操作心智模型。

**首选样板池（以实际可用前置选取，不等于全部一次完成）**：
- 独立挂件：Z91 松果门铃、Z58 门前纸条箱；Z10 迎客灯仍为“修改，需独立专用灯具”，未经确认不作为正式词条。
- 独立／可摆家具：Z56 会客长凳、Z49 木牌认山、Z83 手作签名；可复用当前座椅、指示牌与图案基础。
- 原有宿主上的轻量变化：Z03 灯影温窗、Z05 旧木留纹、Z06 墙根生苔，可先作为可见效果／表面表现，不迫使每种变化都生产新 Item。

**必须有的结果**：至少一件可以安装／拆卸的独立道具、一个可摆放或可使用的物件，共同贯通图纸和库存；物件普通用途在无奇趣词条时照常成立；物件身份、模型、稀有度／词条在制作、安装、移动、卸下与重进游戏后保持一致；远处查看、近身操作清楚且不会误扣原料。营地可明显看出制作前后差别，默认镜头和手机上可辨认。

**本阶段不做**：全套“住”类清单、复杂自动机械、澡堂整套、宠物模拟、完整天气／温度经济；不为了展示数据表而给玩家暴露开发者字段。

### 阶段二：从单件变成可拓展的制作／设施系列

**目标**：玩家有明确的加工成长：简单手作之后，能借助工坊升级和更合适的图纸完成框架、可动部件、结构附件和成套设施。物件可以换形、换外观和逐步改良，而不需要维护永久散件数据库。

**建议系列**：
- 木工与收纳：Z31、Z32、Z33、Z35、Z37、Z40、Z89，结合现有负重、材料打捆、可摆放家具与物理岛；容量效果必须先有真实受量，不能为了词条擅自给所有仓库加新容量上限。
- 家宅与工坊：Z54 屋脊报风鸡、Z55 檐下折叠工台、Z59 屋檐接雨、Z71 火边皮影、Z75 余温石座、Z80 咯吱摇椅、Z77 炭灰拓印、Z100 年轮留言桩；按支架、转轴、可动件、图案、事件记录共享能力分组。
- 热源和日常设施：Z26 慢燃、Z28 挡风火床、Z73 铜壶报沸、Z74 添柴小机关、Z78 雨夜炉罩、Z79 炉温彩陶；按需要补最小燃料／热度／遮雨条件，不能把昼夜自动亮火当真实燃料消费。
- 澡堂作为**独立设施设计前置**：先定浴室、浴桶、热源、水位、角色操作点、洗衣去向，再评估 Z13、Z18–20、Z61、Z63–65、Z68。现有没有澡堂，不能把这些直接标记为已可用。

**必须有的结果**：同一制作系列能够复用图纸、形体参数、装配规则和模型资产，而不是一个物品一套特判；简单制作和复杂工艺在玩家感知上有区别，但不要求玩家做高精度机械操作；模型／贴图／可动件与材质预算在默认镜头下协调，普通用品不靠奇趣词条才获得基础功能；资源和事件结算遵守已存在的一份库存与一个时钟。

**本阶段不做**：完整室内空间、全局刚体模拟、逼真传热流体、长期动物社交；未建成的设施词条保持计划态。

### 阶段三：高阶奇趣行为与多词条组合

**目标**：在有本体、普通用途和稳定触发事件的前提下，逐步开放高辨识的“物件有性格”与史诗／传说级特殊表现。稀有能力的门槛来自合适的图纸／事件／来源与内容定位，不等于要求玩家能手工制造不可思议的复杂机构。

**样板方向**：
- 活道具：Z51 帐篷伸懒腰、Z57 扫帚不听话、Z60 守夜木偶、Z81 木箱大胃王、Z82 抽屉打喷嚏、Z86 木偶质检员、Z90 夜班工具。
- 夜间生活与来访：Z45 篱下萤光、Z46 鸟屋有客、Z47 鹿畔清晨、Z48 窝有暖灯、Z72 围炉夜话、Z96 宠物窝抢座、Z97 蜗牛快递站；必须先有对应人物／动物／信件事件或宠物归属。
- 篝火和高级 VFX：Z21、Z22、Z23、Z24、Z25、Z27、Z29，以及澡堂的修改候选 Z11、Z12、Z15、Z16、Z17、Z67、Z69、Z70；只在设计方向和性能门槛明确后择优进入实现。不能把“颜色参数”当作已经决定了“颜色反应”的触发因果。

**必须有的结果**：至少一种独立物件能从正常用途升级成有差异的高阶行为，并与其他类别的词条合法并存；受限于物件用途、触发源和实际场景；默认视角明显但不喧宾夺主，昼夜不过亮，低性能和减少动态条件下可降级或关闭；动画不直接结算经济，不能通过独立特效复制资源、绕过图纸或让宿主凭空产生收益。

**本阶段不做**：为了凑齐100条强行开启所有修改项；不在已有世界能力缺席时伪造天气预测、完整宠物生活或自动制造收益。

## 五、阶段交接与美术边界

1. **阶段验收以玩家能做什么为主**：每阶段给出真实可玩的前后对比、至少一个完整道具实例链及正常失败路径；只建注册字段、占位模型或“UI 可点”不算交付。
2. **复用优先**：先寻找 CC0 或许可允许改造、游戏使用与仓库再分发的现成模型/贴图/动画，按当前低多边形塑料玩具比例修整。纹样、颜色、数值和重复 VFX 归并成参数，不因 RGB 或单个数值变化重复建立词条；开放素材须记录来源许可。
3. **建模层级**：普通几何优先按现有参数化模板；局部运动优先少数可动子节点；皮影、印记、铭牌可共用图案库。特殊泡泡、史莱姆、蒸汽朋克管路等先做资源和画面成本判断，不能把复杂资产伪装为一张贴图。
4. **保持场景操作优先**：承接 HUD_INTERACTION 的“查看 → 走近 → 操作”、物品页和图纸；不在常驻 HUD 堆砌物品属性、各阶段技术术语或说明书。更多详情按需进入对象详情。
5. **工程边界**：单一世界时钟、统一物品归属、整笔制作／交易／升级事务；不要为了词条增加平行库存、独立渲染循环或全地图重物理。实现方案、代码分割、运行库选型与单次 PR 工作量留给 agent 自主判断。
6. **当前开发期验收**：优先当前玩法真实可用、建模一致、性能没有明显倒退、素材可追溯。不让旧试验存档迁移、无关历史截图或发布级合规检查卡住开发；不能把构建通过冒充美术和操作验收。

## 七、给接手 agent 的最终原则

以现有注册、制作、安装、升级、行为和 HUD 成果为起点，不重新造框架。**先有物件及其正常用途，再让它具备被词条改变的特殊行为；能独立制造的附属品尽量独立持有，建筑只提供合理安装关系。**优先做真实、可见、可继续扩展的少量闭环，随后做系列，再做高阶奇趣效果。对玩法前置不成立的内容诚实保留为 planned，不为了赶进度凭空制造系统或收益。
