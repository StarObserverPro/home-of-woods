## 2. 与既有项目约定的关系

[UI 组织复查 R2](scopes/ui-organization-review-r2.md) 已明确厚木框、木作接角和避免细线容器边框。
[粗木界面回接](scopes/rustic-ui-mainline.md) 已采用图标格、集中详情、分页和共享窗口。
[HUD 与操作路径](HUD_INTERACTION.md) 区分常驻信息、目标提示和功能窗口；本轮应延续这些职责。

本轮需要进一步固化的项目选择：

- 组件默认实现承担材料、轮廓、状态和触控规范，业务模块只选择用途。
- 装饰裁切与内容、命中区、焦点分开，避免削角同时削掉关闭按钮或文本。
- 大窗口按实际可用空间组织内容；分页不能靠隐藏溢出伪装成完整适配。
- 沙盒可以展示参数和诊断，但窗口、按钮、标题、安全区沿用相同基础层。
- 参数值以共用源码为事实来源，文档解释其用途，避免复制一套逐渐漂移的数值。

## 3. Saltline：实际观察与边界

本次读取对象是 [realcodebear/saltline-fable-5.2](https://github.com/realcodebear/saltline-fable-5.2) 的第三方镜像。
检视提交为 `09c51774cd77aad750bd2d6c42af2b1020cb668d`。
对应 [README](https://github.com/realcodebear/saltline-fable-5.2/blob/09c51774cd77aad750bd2d6c42af2b1020cb668d/README.md) 明确自称镜像，并指向 Felix Rieseberg 的原始帖子与 Claude artifact。
本次未独立验证原帖的生成时间、费用、模型或“一次提示”过程，不将这些转载说法作为工程依据。
以下是对该提交 [index.html](https://github.com/realcodebear/saltline-fable-5.2/blob/09c51774cd77aad750bd2d6c42af2b1020cb668d/index.html) 的源码观察：

- 材质定义区分纹理集合与实例颜色、粗糙度等参数。
- 材质工厂对纹理集合、生成 shader 和实例材料分别缓存。
- 提供确定性随机数、质量参数、预热、纹理内存与生成耗时统计。
- 材质生成失败时能返回纯色材质，基本对象仍可显示。
- 模块有独立展示入口；URL 参数可指定 seed、展示对象和相机。
- 木材以共同的方向结构、节疤和裂缝影响颜色、高度及表面属性。

**项目选择：** 借鉴集中生成、缓存、稳定输入、独立检视和回退机制，独立编写适合本项目的实现。
该示例的木纹包含高频纤维、锯痕与风化层；森林之家 HUD 只保留少量粗纹和切面，不复制这种细节密度。
检视提交未找到明确的项目级许可证；公开可读及镜像署名不等同于可复制再分发许可。
本轮不复制其代码、shader 或素材，也不将镜像标记为 CC0 来源。

## 4. 材料与界面用途的映射

以下均为本项目设计选择，不宣称是外部技能规定的通用规则。

| 材料表达 | 主要职责 | 使用限制 |
| --- | --- | --- |
| 纵剖顺纹 | 按钮正面、标题板、主要可读平面 | 木纹沿木料长轴；文字区降低纹理对比和密度 |
| 横截端木 | 板材端头、少量徽标、旋钮或独立标记 | 不把每个方槽都做成树桩，不把大窗口做成巨型截面 |
| 树皮 | 最外周保护边、粗木构架、少量分区 | 不在每层嵌套容器重复树皮黑框 |
| 刨花、木片 | 制作或取得材料的短暂反馈 | 不覆盖文字，不常驻飘动，不承担唯一状态信息 |

粗犷感主要由轮廓、切面、板材厚度和少量缺口建立。文字、对齐、间距和命中区保持稳定。
木头深浅变化表达材料差异；选中、错误、禁用等状态仍需有明确的形状、标记或文字反馈。
同一界面不为每一行信息添加独立木框，优先通过留白、明暗面和组织关系分组。

## 5. 用途先于长宽比

| 用途 | 形状族 | 尺寸变化的处理 |
| --- | --- | --- |
| 紧凑动作 | 短木块 | 保留足够命中区，切角与厚度有上限 |
| 长动作、标题 | 顺纹长板 | 延长板面和纹理段，端头与削角不等比拉长 |
| 大型窗口 | 拼板或厚木构架 | 增加板段与内容空间，避免放大一张按钮皮肤 |
| 窄竖控制区 | 立木 | 木纹沿长轴，宽度仍由可读性和操作决定 |
| 小徽标、旋钮 | 端木片 | 少量使用，保留可识别的状态标记 |

轮廓应先根据用途和尺寸选族，再参考长宽比调整；大正方窗口不因此变成圆木截面。
切口、厚度、崩口幅度由短边和像素上下限控制，不能只用百分比坐标整体拉伸。
程序化色块与纹理从稳定 seed 生成；重新打开或切换状态不随机换一块木头。
禁止通过每帧重画纹理维持静态 UI；按需要生成、复用缓存，并有低成本回退。

## 6. 状态与可访问性的准确边界

[W3C 非文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast) 要求必要的控件和状态视觉信息与相邻颜色满足相应对比。
其说明特别指出，极细图形的抗锯齿可能削弱实际可见对比；常态细线不是可靠的唯一边界。
该准则也不要求所有按钮都画出命中区边框：清楚的文字或图标可以帮助识别控件，但焦点仍须可见。

**项目选择：** 取消装饰性细框，同时保留宽、明确的键盘焦点；焦点不被木料裁切遮住。
优先用原生按钮、输入与选择控件承载行为，装饰层不拦截指针，也不承担可访问名称。
选中状态与键盘焦点是两件事，两者同时出现时仍应可分辨。

[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) 对 AA 最低尺寸规定为 24×24 CSS px，并列出间距等例外。
同页说明增强级目标为 44×44 CSS px。
**本游戏统一的 44px 触控目标是项目准则**，沿用 [ART_HUD](ART_HUD.md)，不将其误写为 WCAG AA 的通用硬性要求。
不规则装饰之外保留完整矩形命中区，可避免削角造成实际目标缩小。

## 7. 建议纳入正式合同的检查项

- 所有新模块和沙盒从共享窗口、表面、按钮与分页入口组合，不另建一套木框。
- 检查默认、悬停、按下、选中、禁用、加载、错误和键盘焦点；不只验静态默认图。
- 覆盖短标签、长中文名称、数量增长、空态与原因文本；文字区没有高对比木节干扰。
- 覆盖桌面、320px 窄屏和 844×390 横屏；标题、关闭和主动作可操作，无隐藏溢出。
- 检查装饰阴影和焦点的绘制余量，避免祖先容器裁掉厚度或焦点。
- 实际操作鼠标与键盘，检查菜单输入不穿透场景；触控仿真与真机证据分开说明。
- 减少动态效果时保留状态变化；生成失败时纯色切面仍能识别控件。
- 复查稳定 seed、缓存复用、卸载与重开；静态 UI 不持续消耗生成成本。
- 新增检查针对本次共享组件与迁移面，不把无关历史用例变成整项目发布门槛。

上述条目适合进入 UI 合同；AGENTS 只需保留共享入口、必读合同和可见验收要求，避免重复整份设计说明。
