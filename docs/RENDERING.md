# 渲染与模块管理

状态：首版架构约定，代码尚未建立。借鉴水晶花园的单一运行循环、道具更新注册、空间查询、资源释放和 HUD 分层；按小型可编辑森林重新整理。

## 模块边界

| 规划目录 | 职责 | 边界 |
| --- | --- | --- |
| `src/content/` | 树木、作物、配方、模型规格、静态地图意图与文案 | 不持有运行时对象 |
| `src/world/` | 解析地图、地表高度/法线、格位与静态边界查询 | 纯数据与查询，不依赖 Three.js |
| `src/domain/` | 角色、库存、成长、交互规则、建筑与动态占地、存档数据 | 不依赖 React、DOM 或 scene |
| `src/scene/` | 模型、灯光、相机、拾取、实例绘制、动画与渲染生命周期 | 读取世界和玩法快照；动作以意图回传 |
| `src/ui/` | HUD、面板、工具栏、响应式布局、键鼠/触控提示 | 不复制材料结算、成长或占地规则 |
| `src/app/` | 组装运行时、命令分发、状态同步、唯一存档写入 | 组合根不堆积模型与业务实现 |

允许的依赖：world → content；domain → world/content；scene → world/domain/content；ui → domain/content；app 组装以上各层。scene 与 ui 通过 app 传递类型化事件和快照，不互相导入。

## 唯一所有者

| 对象 | 首版所有者 | 约定 |
| --- | --- | --- |
| renderer / scene / camera | `scene/create-scene` | 创建一次、显式销毁；镜头控制通过此入口协调 |
| requestAnimationFrame | `app/runtime-loop` | 全应用一个帧调度入口，统一推进游戏 tick 与场景帧 |
| 游戏状态与命令 | `domain/game-state`，由 app 持有实例 | 所有操作经命令验证后提交 |
| 地表坐标 | `world/surface` | 行走、种植、建造、拾取与模型共用查询 |
| 动态占地 | domain 的空间状态 | 随树木/建筑的增删一起更新 |
| GPU 共享资源 | `scene/resources` | 缓存、引用计数或等价所有权机制统一管理 |
| 视觉道具更新 | `scene/prop-runtime` | 在主循环中登记、更新、注销 |
| 交互目标 | `scene/interaction-registry` | 由稳定实体 ID 映射 hit target，回传 action intent |
| 存档写入 | `app/save-controller` | 独立键 `home-of-woods-save-v1`；模型与 HUD 无直接写入权 |

以上名称用于确定责任，可在首次实现时调整文件组织并同步本文。首版不迁入水晶花园的三角网细节、园区业务或既有存档。

## 帧与生命周期

主循环按输入意图、domain tick、快照同步、视觉更新、render 的顺序运行。固定步长推进玩法，限制单帧补步量；移动和动画可做插值，帧率不改变成长或收益。

- `start/resume` 重复调用不会产生第二条 RAF；`pause` 取消待执行帧；`destroy` 幂等且销毁后不能恢复。
- 页面隐藏、暂停菜单和失去图形上下文时停止玩法推进与渲染；恢复时重置帧时间基线，避免一次推进很长时间。
- 普通背包/对象面板只屏蔽被 UI 占用的输入；是否暂停由统一模式决定，组件不各自启停循环。
- 树叶摇摆、砍树反馈和建造粒子登记到视觉更新入口，不自建常驻 RAF 或定时器。
- 对象卸载时移除命中项和更新项、取消延迟任务/异步回调、归还资源；回调必须检查生命周期，不能复活已销毁对象。
- 应用卸载还须释放输入监听、ResizeObserver、渲染目标、资源缓存、renderer 和 canvas。

## 空间与可编辑森林

首版采用简单地表查询与占地格即可。人工配置、解析后的世界位置、玩法状态、装饰表现各有归属：

- **地表：** 地面、道路、农田的高度与可行走语义来自同一查询。地表每处只绘制一份基础表面；土地颜色/材质变化用同一表面表达。
- **实体：** 树木、建筑、田块与大型石头以稳定根位置和 footprint 登记；模型在根节点下使用局部坐标。
- **装饰群：** 无玩法的草叶、落叶和小石头按区域 seed、密度、占地排除规则生成；复用相同地表查询。
- **短时效果：** 木屑、尘土、提示圈只承担反馈，不决定掉落、碰撞或存档。

场景卸载只移除表现，不能让树重新长回、重置田地或重新发放物品。实例拾取必须通过 instance → entity ID 映射回到 domain；增删实例后同步映射与包围体。

## 资源与扩大地图

1. 重复树木、石头、围栏优先共享几何和材质，同类静态外观可使用 InstancedMesh。可交互树仍保持独立的 domain 身份。
2. 资源区分“对象独占”与“缓存共享”。对象只销毁自己的资源；共享几何、材质和纹理由缓存计数归零后释放，避免遍历销毁邻居仍在用的资源。
3. 生长阶段变化先切换缓存模型或实例参数；逐帧不重新生成几何、纹理、材质或临时数组。
4. 首版只加载一块小地图。扩大时按 chunk 管理模型、命中项和装饰，记录加载范围与回收范围，并设滞回避免边界抖动。
5. chunk 外保留玩法数据；卸载几何不删除实体状态。远处降低模型细节、阴影和装饰密度，不能移除真实的资源或建筑。
6. 材质/几何缓存键包含规格、变体和版本；持久或验收场景使用固定 seed，不能靠 `Math.random()` 重建。

## 画质与验收

首版使用有限材质、一个主方向光和柔和环境光。动态阴影限制范围与投射对象，DPR 设上限；后处理、反射和实时生成贴图在确有视觉收益时再加入。

性能目标暂定桌面 60 fps、选定移动设备稳定 30 fps；属于待测目标。首个视觉小样记录具体设备、浏览器、分辨率、实体数、draw calls、三角形数、纹理/几何计数和帧时间，再定预算。

视觉改动使用固定 seed、相机、时间和状态截图。生命周期验证覆盖暂停/恢复、反复进入退出、砍树后存读档、建筑增删，以及后续 chunk 往返；预热后资源计数应收敛，不随重复操作持续增加。降低画质不能改变玩法结果。
