# 五动作与木料用途接入

本次以已合并 main `6135733` 为基线，抽取已接受的 R3 动作沙盒表现。PR #3（M0 山谷）和 #4（角色、采集仓库、完整存档、R5 场景）均已合并；其旧目录和证据保留为历史档案。本次实现仍待独立 PR 审查，未合并、未部署。

## 场景接线与结算

| 操作 | 入口与表现 | 状态与结算 |
| --- | --- | --- |
| 地面捡碎柴 | 独立碎柴堆，弯腰拾起、随手提起并收好，3.2 秒 | 独立 sourceId；完成后扣一次来源、入库 3 份燃料。取消恢复地面显示，不发物品。 |
| 上树采枝 | 选宿主树→上树采枝，或选树上枝杈来源；抱树、抬腿、蹬一步、拉远和树冠晃动，8 秒 | 沿用旧 branches sourceId 与宿主代次；原落枝名称迁移为树上枝杈，旧库存不转换成碎柴。完整动作结束后一次提交。 |
| 采蘑菇 | 蘑菇圈→采集；蹲下、左右动手，镜头转身后，5 秒 | 同圈仍共享来源池；动作结束后一次提交，取消不扣池。 |
| 伐木 | 经营树→走近→砍树；根据人物站位冻结倒向 | 切断时一次提交额度/产物/树状态；下部替代树干、成对断面、断口支点、脱离与地形接地。倒木停留 1.8 秒后隐藏，树桩仍可选。 |
| 祈祷 | 祭坛→合掌祈祷；走到坛前、合掌低头，5.5 秒 | 与采集/采伐互斥；应用时钟驱动，完成显示安静回应，不扣供品、不发奖励。祭祀待开放，拒绝未配置扣物。 |

祈祷与祭祀共用姿态能力，供奉的正式供品、数量和奖励规则未确定，因此祭祀按钮明确待开放。碎柴的稀有小木料概率、数量和恢复周期也未定；`SCRAP_RARE_DROP` 保持 null，本版没有抽奖、保底或读取时重抽行为。正式恢复仍未启用。后续启用时必须在来源生成/合法恢复时冻结稀有结果并持久化，不能在点击时抽取。

选材能力不等于开放制作。篝火的昼夜明暗仍是已接受的场景表现，没有悄悄增加燃料消费；正式制作、供奉与篝火消费流程需使用本次选材事务。

## 唯一库存与用途注册

- `content/wood-uses.ts` 注册物品用途资格、aggregate/piece 用途和规则版本。碎柴只有 fuel；枝料、小木料与原木的其他资格独立登记。
- 库存身份扩展为 itemId + qualityId + 可选 wood 批次元数据。相同规格可堆叠，不同长度、直径、顺直程度或保留状态不能混并。`stackKey` 是稳定批次键；不另建燃料余额。
- 计量目前明确为完整的“件/份”：`measureId: piece, amountPerPiece: 1`，不声称质量或体积等价。aggregate 需求按合格份数选具体批次；piece 需求逐件检查毫米长度、圆木直径与顺直分档，短木不能相加冒充长木。板材宽厚、切分和损耗尚未开放。
- 初始采枝规格为 800 mm 长、40 mm 直径、弯曲；采伐结果登记 3000 mm 长与按经营树比例确定的直径、顺直。这是首版游戏规格，不是从历史库存反推的尺寸。规格在动作开始时冻结进 reward，结算和读档不按新配置改写。
- 旧库存 wood 元数据缺省代表未知，详情明确显示未测定；单件尺寸用途拒绝未知规格。允许旧泛料的总量用途可使用它。
- `domain/wood-selection.ts` 先筛用途资格，再逐批核验；更受限的 piece 需求优先，共享一份预占表。候选绑定库存 revision、完整批次指纹与规则版本；提交重算资格并一次扣除和产出，失败不部分扣料。读档重置 revision 也不能使旧候选重复消费。
- 已保留料不自动选中；aggregate 默认不烧原木、精品或顺直料，调用方只有明确取得选用意图后才传 `allowValuable: true`。没有后台自动烧材。

## 存档与回退

世界容器 schema 仍为 1，ruleset 从 1 升到 2；库存持久化切片 schema 升为 2，旧 schema 1 与早期 quantities 切片继续读取。运行时规范化库存仍使用原有 revision API。世界仍由 save-controller 的一个 IndexedDB 事务写主档/备份。

ruleset 1 先验证旧来源集合与校验和，再添加新碎柴来源。原树位、代次、额度、库存和旧来源剩余量完整保留；旧进行中采集取消，避免把旧即时拾取继续当作上树。已经完成的历史记录仍保留。未来结构和坏数据继续 protected，不覆盖有效存档。

回退代码需同时保留 ruleset 2 原档。旧客户端会拒绝新 ruleset，不能把旧格式文件覆盖到新档；应从回退前导出的有效副本恢复。测试使用独立本地 origin，没有清除用户存档。

## 表现、资源与检视

主体只引用 `src/scene/actions` 中的表现模块，不引用沙盒入口、地台、模型副本或动画循环。现有 KayKit/项目树/枝束/蘑菇 GLB 不变。中等经营树的静态合批与动态替代共用同一几何构造；巨木保留原模型尺度。倒伏采样统一 `heightAt`，含横坡和非平面地表；发起采伐时检查倒向区域的障碍和水岸，受阻提示换侧站位。角色撤步和采集接触消费同一地表。

共享原始资源仍由 Resources 释放；动作适配器仅释放自己创建的几何、材质、骨架。没有新增 RAF、定时发奖或第二存档写入者。自动取景不改用户 yaw/zoom；手动转动/缩放取消当前动作自动取景，动作结束/取消恢复普通镜头，减少动态关闭自动取景。

`?inspect=1&hour=14` 可固定审看光照；诊断面板的“下一动作接触停帧”和秒数输入在真实动作到达指定时间后暂停唯一循环。结束动作检视继续原动作，不重新发奖。普通产品入口不显示这些检视控件。操作目标按钮前收起诊断面板，以免面板遮挡。

沙盒保留为已接受设计的归档，后续生产修改以主体和本文为准。测试及实际画面见 [集成证据](../evidence/action-wood/README.md)。
