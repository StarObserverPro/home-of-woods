# 食物基础闭环

2026-11-05：本地营地生活回接已包含 P2 节律、P3 有限食物替换与 F100 代表行为。当前取得/消费、真实木碗持握、生活日与座位安全合同统一见 [CAMP_LIFE_INTEGRATION](CAMP_LIFE_INTEGRATION.md)；本文保留基础加工合同及未列入本批的后续方向。

目标：先建立共用的数据和交互基础，能一笔交易取得混合干粮、真实晾干蘑菇、做出并吃掉一碗正餐；食用影响**下一生活日（06:00 换日）**是否能进行成熟树采伐。此范围不替代现有 M1/M2 里程碑，也不代表奇趣词条或生活节律系统完成。

完整 P1–P4 目标与先后见 [食与生活四阶段规划](FOOD_LIFE_PHASES.md)，原初版“二阶段”条目只保留历史候选含义；后续获准实施的代表范围和真实前置以 [当前推进映射](CAMP_LIFE_PROGRESS.md) 为准。

## 已施工的共享基础

- **物品身份**：鲜蘑菇使用既有 `mushroom`；`dried-mushroom` 从 planned 改为 active。干豆、燕麦、米、黑面包、盐、香料和菌菇汤注册在 `src/content/items.ts` / `item-types.ts`。同类汤用单一 `forest-soup` ID 加可序列化的 `food.series/grain/fungus` 元数据区分，不制造无数菜谱。
- **行商包裹**：当前常规商店由现有 `supply.food` 提供真实 `trail-rations` 粮袋，明确拆袋时在同一库存事务中移除 1 袋并结算确定性配比的干货，不能同时保留整袋与内容物。`food-sack` 的基础交易意图仍由原事务入口处理；当前购买价格、库存与赊账以 [行商合同](MERCHANT.md) 为准。本模块只维护拆袋配比序号，不另建商人、补货时钟或 NPC AI。
- **加工**：`dry-mushrooms` 复用既有 `PROCESSING` 与采集注册层，2 份鲜菌 -> 1 份干菌，持续 100 游戏秒；下料时原子扣除，世界时间到期后只入库一次，可跨存档。
- **烹饪**：火塘已有挡风石圈→锅架→悬钩基础图纸链。新增同宿主的基础悬挂汤锅（按图纸使用行商五金制作），只有悬钩当前挂载时才显示并可煮汤。1 份鲜/干菌 + 1 份豆/燕麦/米 -> 1 碗菌菇杂粮汤。扣料、完成入库、消费都使用统一库存事务。当前火塘用餐先通过安全座位预检，真实消费后播放持碗或持面包进食；一根原木可制作独立手作木碗，无词条即可盛汤/粥，F100 仅在实际用餐后追加短表现。远行容器与完整厨房仍按后续前置推进。
- **用餐**：火塘旁享用一份成品汤、粥或黑面包后，更新 `food.lastMealDay`，并保留已有的当前生活日资格。生活日在 06:00 换日，吃饭为下一生活日的成熟树采伐与新搬取原木做准备；午夜后的进食仍服务眼前的日出。不吃不会饿死，仍可散步、采菌、捡枝和搬轻料；**开局第 1 个生活日默认能劳动**。黑面包无需先制作汤锅即可食用，避免重活资格与制锅原木互相锁死。
- **世界状态**：`GameState.food` 记录进食日、粮袋序号、两种加工任务和计数。世界存档的 `food` 新字段允许旧记录缺省，读取时补新手缺省；严格校验已保存任务的时间和身份。没有影子 localStorage、定时器或二次 inventory writer。

## 交互及可见边界

在行商处兑换整袋粮食；在场景中点选晾晒架并走近，先用开局基础图纸和两份枝杈搭建，再开始晾晒；点选火塘、通过既有升级面板安装锅具后煮汤与用餐；未装锅时仍能吃行商硬黑面包。远处能看见“走近”，距离合适才检查库存不足。晾晒架与汤锅使用场景本身的简易低多边形几何体，未建成的晾晒架没有架体、仅保留可操作的施工点，无新外部模型授权；晾晒架仅在加工进行中显示蘑菇串。没有增加独立厨房地图或锅内放大镜。

## 验证范围

`tests/food-foundation.test.ts`：粮袋序号及配比、材料不足交易原子性、晾晒到期单次结算、干菌/谷物制汤与成品属性、用餐消费及次日资格、无食物旧世界的缺省。整仓 `npm run check` / PR CI 与正常镜头实际操作证据须另行报告，不能拿类型通过代替视觉验收。

## 后续扩展（未列入本批）

1. **食材与供应**：扩大森林可采菌种、浆果、橡实等，决定对应的安全性与加工方法；混合粮袋价格/数量与独立 NPC 经济模块、季节供货机制对齐，不在本模块复制行商日程。
2. **烹饪结果**：将“蘑菇+谷物”扩展为少量汤/杂烩/热饮系列，由食材标签和器具能力分类，而非几百张具体菜谱；野外食盒与可复用容器等后续再接入；黑面包直接食用及三种谷物的汤/粥替换已开放。
3. **工艺设施**：晾晒架遮雨 F33、盐渍、发酵、橡实去涩/粗磨、烟熏和烙饼按可复用加工服务接线，不为每种食材造一件厨房家具。锅具先按固定升级件实现；若变成可独立持有/摆放的实例，需明确一次升级账本到独立 Item 的迁移，不可复制成两份。
4. **生活节律与负重**：夜间休息、故事阅读与 06:00 生活日资格已共用现有时钟；原木取放与伐木已接 `heavyLaborAllowed`；重木作等剩余劳动门槛以后由对应系统接入，不要把大型通行限制偷偷并进烹饪 service。
5. **奇趣词条**：保持 F01–F100 已评审状态，先验证烟雾塑形、陶坛整体动作、木勺联动、幻影和用餐事件等共用演出能力；NPC 帮厨、试味与食记是独立行为事件，不在基础加工服务里写死。
6. **视觉/性能验收**：独立确认桌面/手机正常营地镜头可读性，补食材与器具实际使用时的人物动作，限制特效不侵占火焰/材质预算；首阶段灰盒不是奇趣词条验收。
