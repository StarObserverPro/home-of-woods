# 食物基础闭环 · 第一阶段（独立功能分支）

> 历史 P1 实施记录。P1 已随 PR #21 合批进入 main；以下「第二阶段」是当时尚未施工的候选范围，不代表现在的执行顺序。当前阶段目标与优先级以 [「食」与日常生活四阶段总纲](FOOD_LIFE_PHASES.md) 为准。

目标：先建立共用的数据和交互基础，能一笔交易取得混合干粮、真实晾干蘑菇、做出并吃掉一碗正餐；食用影响**下一游戏日**是否能进行成熟树采伐。此范围不替代现有 M1/M2 里程碑，也不代表奇趣词条或生活节律系统完成。

## 已施工的共享基础

- **物品身份**：鲜蘑菇使用既有 `mushroom`；`dried-mushroom` 从 planned 改为 active。干豆、燕麦、米、黑面包、盐、香料和菌菇汤注册在 `src/content/items.ts` / `item-types.ts`。同类汤用单一 `forest-soup` ID 加可序列化的 `food.series/grain/fungus` 元数据区分，不制造无数菜谱。
- **行商包裹**：沿用 `tradeSupply` 的一次交易入口；`food-sack` 是一次**整袋交易意图**，不另造一份无限容量的库存物品。确定性生成不同配比，一次事务消耗 2 份鲜菌、结算所有干货，入库后可分别消耗。调味品不是每袋都有，主食始终有若干份；价格是本轮示范数值，未来与行商经济统一调整。没有追加第二个商人、补货时钟或 NPC AI。
- **加工**：`dry-mushrooms` 复用既有 `PROCESSING` 与采集注册层，2 份鲜菌 -> 1 份干菌，持续 100 游戏秒；下料时原子扣除，世界时间到期后只入库一次，可跨存档。
- **烹饪**：火塘已有挡风石圈→锅架→悬钩基础图纸链。新增同宿主的基础悬挂汤锅（按图纸使用行商五金制作），只有悬钩当前挂载时才显示并可煮汤。1 份鲜/干菌 + 1 份豆/燕麦/米 -> 1 碗菌菇杂粮汤。扣料、完成入库、消费都使用统一库存事务。第一阶段用餐仍通过火塘操作界面结算，木碗只是概念占位，尚没有制作、持握和喝汤动画；不额外制造餐具库存或面向远行的物理容器。
- **用餐**：火塘旁享用一份成品汤后，写入 `food.lastMealDay`。不吃不会饿死、不产生逐动作体力或连续饥饿数值；在之后一个游戏日允许正常成熟树采伐和新搬取原木，没吃则仍可散步、采菌、捡枝和搬取轻料。**开局第 1 天默认能劳动**；此外，行商粮袋里的硬黑面包可直接作为一份基础口粮食用，无需先制作汤锅，避免开局过了第一天却没原木做锅、又不能砍树的循环锁。持续到更远的下一天需要再吃一顿。
- **世界状态**：`GameState.food` 记录进食日、粮袋序号、两种加工任务和计数。世界存档的 `food` 新字段允许旧记录缺省，读取时补新手缺省；严格校验已保存任务的时间和身份。没有影子 localStorage、定时器或二次 inventory writer。

## 交互及可见边界

在行商处兑换整袋粮食；在场景中点选晾晒架并走近，先用开局基础图纸和两份枝杈搭建，再开始晾晒；点选火塘、通过既有升级面板安装锅具后煮汤与用餐；未装锅时仍能吃行商硬黑面包。远处能看见“走近”，距离合适才检查库存不足。晾晒架与汤锅使用场景本身的简易低多边形几何体，未建成的晾晒架没有架体、仅保留可操作的施工点，无新外部模型授权；晾晒架仅在加工进行中显示蘑菇串。没有增加独立厨房地图或锅内放大镜。

## 验证范围

`tests/food-foundation.test.ts`：粮袋序号及配比、材料不足交易原子性、晾晒到期单次结算、干菌/谷物制汤与成品属性、用餐消费及次日资格、无食物旧世界的缺省。整仓 `npm run check` / PR CI 与正常镜头实际操作证据须另行报告，不能拿类型通过代替视觉验收。

## 第二阶段（尚未施工）

1. **食材与供应**：扩大森林可采菌种、浆果、橡实等，决定对应的安全性与加工方法；混合粮袋价格/数量与独立 NPC 经济模块、季节供货机制对齐，不在本模块复制行商日程。
2. **烹饪结果**：将“蘑菇+谷物”扩展为少量汤/杂烩/热饮系列，由食材标签和器具能力分类，而非几百张具体菜谱；面包的食用、复用粮袋、野外食盒等后续再接入。
3. **工艺设施**：晾晒架遮雨 F33、盐渍、发酵、橡实去涩/粗磨、烟熏和烙饼按可复用加工服务接线，不为每种食材造一件厨房家具。锅具先按固定升级件实现；若变成可独立持有/摆放的实例，需明确一次升级账本到独立 Item 的迁移，不可复制成两份。
4. **生活节律与负重**：夜间休息、故事阅读、翌日劳动资格的更复杂结算交由生活节律分支；原木取放与伐木已接 `heavyLaborAllowed`；重木作等剩余劳动门槛以后由对应系统接入，不要把大型通行限制偷偷并进烹饪 service。
5. **奇趣词条**：保持 F01–F100 已评审状态，先验证烟雾塑形、陶坛整体动作、木勺联动、幻影和用餐事件等共用演出能力；NPC 帮厨、试味与食记是独立行为事件，不在基础加工服务里写死。
6. **视觉/性能验收**：独立确认桌面/手机正常营地镜头可读性，补食材与器具实际使用时的人物动作，限制特效不侵占火焰/材质预算；首阶段灰盒不是奇趣词条验收。

## 当前未覆盖

没有完整的坐下喝汤人物动作或用餐阅读 UI；没有完整日夜休息转换；没把劳动资格扩展到全部搬木/施工；干货不腐败、不计算营养学；没有实时 API 调用，也没有新增人物模型。首阶段新锅、晾晒架模型为本仓库简单原创几何，不应宣称成品美术验收。
