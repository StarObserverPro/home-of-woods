# 木料用途注册与库存选择方案

2026-10-30。设计提案，尚未接入主体。依据用户决定：用途分为只关心总量、关心单独尺寸两类；木料保留长度、粗细、顺直程度。用途模式属于需求，不是把同一份木头复制成两个库存。

## 两类需求

| 模式 | 例子 | 校验与消耗 |
| --- | --- | --- |
| aggregate：按总量 | 篝火燃料、制造辅料 | 在合格物料中累计明确单位的总量，不检查单根长度；产出必须仍消耗具体库存批次。 |
| piece：按单件规格 | 主材、雕刻坯料 | 每一件分别满足长度、粗细、顺直程度及材料条件；几根短木不能相加冒充一根长木。 |

“辅料”不是任意木材都能用。碎柴目前只有 fuel 资格，可以生火，不能用于制造辅料或其他制作；小木料、枝料、原木的资格分别注册。同一种合格小木料可以满足两种需求，但只能实际消耗一次。

## 三张注册表和一份库存

1. 物品定义：稳定 itemId、材料/树种、形态、用途资格 capabilityIds、计量规则引用。记录“是什么、允许做什么”，不将所有配方 ID 塞进每个物品。
2. 用途定义：稳定 useId、aggregate/piece 模式、必需资格、允许材料/形态及计量单位。例如 campfire.fuel、craft.auxiliary-wood、craft.primary-stock、carving.blank；名称为方案示例。
3. 配方需求：引用 useId，再给数量或单件规格条件。用途给基础限制，具体配方只能增加限制，不能放宽碎柴的燃料专用规则。
4. 权威库存：统一持有批次和数量，候选查询按两种模式投影；不再另存“燃料总库存”和“主材总库存”。

建议的受控结构（未实现）：

```ts
type WoodLot = {
  lotId: string;
  itemId: string;
  qualityId: string;
  count: number;                  // 同规格件数
  spec: null | { lengthMm: number; thicknessMm: number; straightnessId: string };
  amountPerPiece: number;         // 固定计量精度的整数
  measureId: string;              // 显式单位，不能混加件数、质量和体积
};
type WoodRequirement =
  | { mode: 'aggregate'; useId: string; measureId: string; amount: number }
  | { mode: 'piece'; useId: string; count: number;
      minLengthMm: number; minThicknessMm: number; allowedStraightnessIds: string[] };
```

毫米仅是建议的存储精度；粗细的具体测量约定、顺直分档、总量单位及换算系数都待正式数值设计。原木可能用有效直径，板材则应升级为宽厚截面，不能长期用一个“粗细”字段掩盖不同形态。未知规格用 null，不能用零尺寸冒充已测量。

库存优先按同规格批次存储，不必给每根普通木头建独立对象。一个批次中的每件均具有相同规格与单位量；只有单件独有形状、雕刻进度等状态时才升级为实例。碎柴可以用固定单位的散装批次，无需虚构每根尺寸。规格不同即分批，查询总量时可以聚合，不能因此丢弃原批次规格。

## 索引与查询

- 注册时建立 useId → 用途规则、capabilityId → itemIds、itemId → 库存 lotIds 的派生索引，先按资格和材料筛选。
- aggregate 查询再按 measureId 分组累计有效量；换算必须使用显式规则和版本，不能把两种单位直接相加。总量不关心独立尺寸，但仍关心燃料/辅料资格及具体配方限制。
- piece 查询在候选批次上逐批检查单件规格，再累计合格件数。早期数量有限时直接过滤即可；确有性能需要再按长度、粗细分桶，分桶只是粗筛，最终仍须精确复核。
- 所有索引从库存重建，不作为第二份可消费余额，也不随加载重新生成规格。

例如，需要一件足够长的雕刻坯料时，两件长度不足的木料即使总量足够也不能通过；篝火只累计合格燃料的可燃量。这里不规定雕刻的正式尺寸门槛。

## 一次选料与提交

需求解析生成具体 lotId/count/实际量分配，并绑定库存 revision 和规则版本。同一配方既要主材又要辅料时，应优先满足更受限的单件需求，或允许玩家指定；所有需求共享同一份预占表。这样同一根木头不会既算主材又算辅料。

默认保护已保留的木料，不自动烧掉长、粗、顺直或高品质的可用料。燃料与辅料优先选资格合适、用途限制较多的廉价料；可用范围与排序规则显式配置，必要时由玩家确认选料。

总量恰好不足整件倍数时必须定义策略：首版可整件消耗并显示实际消耗量；若支持切分，则一次事务记录切分损耗、消耗量和具有真实剩余规格的新批次。不允许减去一部分总量却仍保留完整的一根长木，也不默认切剩的木头恢复原尺寸。

提交时重新校验所有批次、规格、资格与数量，整笔扣料并生成产物。失败不部分扣减。加工结果冻结实际规格及规则版本，读档不按新配方重算。已有 itemId + qualityId 数量库存需要显式迁移：无法推断的单件规格保留未知，只有明确允许旧泛料的总量用途可使用它。

## 后续实现验收

覆盖同量异形、短木拼长失败、碎柴制作拒绝、同一批次跨需求重复占用、未知规格、单位不匹配、切分守恒、过期候选、重复提交及存档往返。数据设计不改变当前沙盒仅有表现的边界。
