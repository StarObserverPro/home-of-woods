# 动作接线说明

2026-10-30。用户接受 R2 当前表现，并明确以下场景对应关系。本文件为后续接入约定；本次仅写说明，未接入主体，也未授权 PR、合并或发布。

## 场景与动作映射

| 场景操作 | 沙盒动作 | 主体接入行为 |
| --- | --- | --- |
| 地面捡碎柴 | pickup | 拾取地面的碎柴，主要获得生火燃料；极小概率找到极少量小木料，单独登记产物。 |
| 采集树枝、树杈 | climb | 到宿主树前，抱稳、抬腿蹬一步，镜头拉远，树冠晃动；采集完成后回到树下。枝杈需要上树，不沿用地面拾枝表现。 |
| 采蘑菇 | gather | 到蘑菇簇前，下蹲时镜头转至身后，左右采摘、收手起身。目标是实际蘑菇来源池。 |
| 砍树、伐倒 | fell | 面向合法目标树挥斧；最后伐断阶段使用局部树干替代、匹配断口、定向倒伏和接地余振。根桩保留在原树位。 |
| 祈祷 | pray | 在对应祈祷交互点面对目标合掌、低头、停留，再播放该场景的回应。 |
| 祭祀、供奉 | pray | 在对应祭坛面向供奉目标，使用同一合掌动作；供品呈现、扣除条件和回应由祭祀流程控制。 |

祈祷与祭祀共用姿态，不合并为同一种业务操作。各自是否消耗物品、产生何种结果，读取对应场景规则；动作沙盒不提供这些规则。

## 枝杈旧接线的迁移

当前工作目录的 content/gatherables.ts 把 branch 定义为 forage.branch-pile / gather.pickup，描述为地面落枝；content/tree-resources.ts 的 branch 挂点也是 ground。它们与本次用户决定不一致，正式接入时需一起更新名称、描述、动作标签、命中入口与挂点，不能只把拾取动画换成爬树。地面拾取入口仍然保留，改为独立的捡碎柴活动；它与上树采枝使用不同来源定义和资源池。

建议新增明确的上树采枝动作语义（如 gather.climb，名称待实现时统一），由树干命中入口选择宿主的枝杈资源池。树冠资源、树干交互点、人物树下站位分别登记，仍归属同一个稳定 sourceId 与宿主身份。保留既有物品 branch 的语义和库存；旧来源/存档如需换 ID，应提供显式迁移，不因场景加载或换模型重置数量。宿主换代后旧个体目标失效，保护巨木仍禁止伐倒，上树资格由其独立规则决定。

## 地面碎柴与小木料

用户追加决定（2026-10-30）：地面捡的是碎柴，可以生火，不能用来制作东西；只有极小概率刷出一点点小木料。

- 碎柴是独立燃料物品，不复用枝杈或小木料 ID。用途限定为生火，不进入木作、修缮或加工材料配方，也不允许通过整理碎柴稳定转化出小木料。
- 小木料是地面来源的稀有发现，独立于碎柴登记；发现它不改变整堆碎柴的用途。仍保留上树采枝及其后续加工途径。
- “极小概率”和“一点点”是已确定的相对要求，具体概率、数量及来源恢复周期尚未定值；本说明不擅自设成固定百分比或保底次数。
- 实施时在来源生成或合法恢复时冻结稀有产物结果，绑定稳定来源身份与周期/代次并持久保存；点击、取消、重进场景、读档都不重抽。拾取时一次提交来源扣减、碎柴和实际存在的小木料入库。
- 地面活动的表现为走近、弯腰或蹲下拾取、起身；不播放上树动作。R3 已新增第五个沙盒演示按钮，只有动作和道具表现，没有真实库存或稀有掉落。

## 木料规格与未来用途

用户追加决定：木料记录长度、粗细、顺直程度，之后由这些信息参与决定用途。适用于可用枝料、小木料及原木；碎柴仍按燃料资格处理，不因记录尺寸而获得制作资格。

| 信息 | 含义 | 后续用途判断 |
| --- | --- | --- |
| 长度 | 可用木段的长度 | 判断是否满足目标构件所需长度 |
| 粗细 | 可用截面的粗细；圆木可用直径表达 | 判断截面需求与可加工规格 |
| 顺直程度 | 木段的弯曲、顺直情况 | 判断是否适合要求顺直的构件或其他用途 |

三项是相互独立的材料信息，不压成一个“精品/普通”品质等级。具体单位、分档、用途门槛和配方以后确定，暂不承诺某种尺寸一定能制作某物。

接入时新增产物在生成/加工结算时保存规格，库存详情展示三项信息。不能只存在物品目录的默认值里，也不能从模型缩放反推历史库存。相同物品、品质但不同规格的木料不能直接合并而丢失差异；建议采用受控规格档位或同规格批次，确定计量精度后再决定是否需要逐件实例。

当前主体库存仅按 itemId + qualityId 堆叠，尚不能无损保存这些差异。实现需要同时更新堆叠身份、材料选择、加工候选、仓库、存档格式及往返验证；拆分与转移保留规格，加工输出按明确规则生成新规格。旧库存无法还原的三项均保留“未知/未测定”，不随机补值，也不自动满足有规格门槛的用途。

## 接入边界与时序

- content 配置动作标签、持续时间、树种切口与挂点；domain 校验资格、来源、宿主代次、库存及供品，产生候选状态；app 统一调度并一次提交；scene 只消费状态，驱动骨架、局部网格和镜头。
- 使用主体唯一时钟与动作状态。不要导入沙盒 main.js 的独立循环、演示地台、选择器、模型副本或资源结算替身。按职责抽取 actor.js、tree.js、motion.js 的表现能力，并接入主体缓存所有者和卸载流程。
- 通用流程：发起意图 → 合法寻路 → 到位复核 → 动作执行 → app 在约定完成点重新校验并提交 → 成功回应与收尾。动作不能靠手摆动次数、镜头结束或动画回调发资源。
- 枝杈在树冠采集段结束时提交一次，随后下树；蘑菇在采摘完成时提交一次，随后起身；祭祀在合掌完成时验证并提交供品事务，成功后才表现回应。失败时使用失败收尾，不播放成功反馈。
- 伐倒以不可逆的断裂点作为业务提交边界：提交前复核资格与目标；成功后才进入倒伏，并按主体采伐事务原子更新树状态、关联物产及产物。提交失败不让树先倒下。已提交后的取消只中止/快速完成表现，不再次结算或复原成活树。
- 提交前取消不扣资源；移动、切目标、宿主失效、读档与卸载均有明确中止/恢复路径。上树中止需恢复合法树下位置；镜头恢复进入前状态并释放输入占用。暂停、隐藏、存档恢复与重播不得造成重复结算。
- 沙盒时长为演示候选：伐断 7 秒、上树 8 秒、采菇 5 秒、祈祷 5.5 秒。主体当前采集耗时仍有 0 秒配置，接入时需同步配置和动作进度；不要在已经立即发奖之后补播整段动作。

## 伐木与镜头参数

伐断首先适配不超过合抱的中等树形；本版切口处直径约 0.50–0.56m、切口高 0.88m。主体每种树必须重新核对比例、截面接缝、斧刃命中和性能，不直接用同一半径套全部树型。

倒向是一次动作冻结的参数，缺口、连接带、倾倒轴、人物站位/撤步和粒子共同使用。四方向选择器只用于沙盒审看，正式产品由何种交互选择倒向待接入时确定。主体应检查倒伏区域、建筑、水岸与地形，接地读取统一地表事实；沙盒的平面坡度求解需替换为主体地表采样。不能以穿过建筑或落进不可达区域的倒木作为完成结果。

上树镜头在蹬步后拉远，以树冠遮挡省略持续攀爬；采菇镜头在下蹲阶段转向背后。玩家手动操作镜头、减少动态、暂停、取消和场景切换都需要明确优先级及恢复，不持续争抢相机控制权。

## 接入验收

- 地面拾取产出碎柴且只能作燃料；稀有小木料不因取消、重载重复抽取；木料规格在堆叠、拆分及存档往返中保留。
- 枝杈实际触发上树，蘑菇实际触发蹲采，伐木使用目标树切口，祈祷/祭祀对准各自交互场景；不靠审看按钮替代实机触发。
- 两种树、不同尺寸与倒向，在实际地形检查手脚接触、断口匹配、根桩固定、倒木接地及人物撤离；上树期间不允许同一宿主被并发伐倒。
- 覆盖正常完成、提交失败、重复事件、取消、目标失效、暂停、读档与卸载；核对资源守恒和一次结算。
- 固定 seed/相机/状态留桌面与手机视口截图及实际操作记录；沙盒测试与截图只作候选参考，不替代主体集成验证。
